## 2. 選択とホバー

### 2.1 選択の基本規約

| ID | 規約 | 根拠 |
| --- | --- | --- |
| **IX-01** | **選択は常に1つ。** `SelectionTarget` は `{種別, 識別子}` の単一値であり、モードをまたいで1つしか存在しない | `02a` 5章, UXR-06 |
| **IX-02** | **複数選択を提供しない。** 比較が必要な場面（複数候補 E-05）は、選択ではなく**並置表示**で解決する | 選択が複数になると、4面同期の意味が崩れる |
| **IX-03** | **選択は明示操作（クリック）でのみ変わる。** ホバー・スクロール・ズーム・集約では変わらない | UXR-08 |
| **IX-04** | **システムが自動で選択しない。** ページを開いた直後、経路の構成直後、モード遷移直後のいずれでも、システムは何も選択しない（引き継ぎによる復元を除く） | 原則3。「自分が選んだもの」と「勝手に選ばれたもの」を区別できなくなる |
| **IX-05** | **選択できないものをクリックできるようにしない。** ただし**プレビューは例外** — どの要素が特定できるかは事前に分からないため、クリックを受け付け、特定できなければ理由を返す (FR-11b) | `01b` Q-03 確定事項2 |

### 2.2 ホバー

| 面 | ホバー時の表示 | 遅延 | 消え方 |
| --- | --- | --- | --- |
| **F-2 プレビュー** | **特定可能な要素の輪郭のみ**。値・ラベル・バッジを重ねない | 即時 | ポインタが外れたら即時 |
| **F-3 フロー図** | 1行要約（例：`GET /api/properties — 124ms — 200 OK`）+ 観測性の語（実測 / 推定）+ 最弱環なら ★ | **100ms** | 即時 |
| **F-4 詳細パネル** | リスト行の強調（対応するフロー図のノードも強調される — 弱い同期） | 即時 | 即時 |
| **N0 インジケータ** | 状態の1行説明（例：計装「適用不可：外部で起動されたサーバーに接続しています」） | 300ms | 即時 |

| ID | 規約 |
| --- | --- |
| **IX-06** | **ホバーで詳細パネルを書き換えない。** 読んでいる最中に内容が入れ替わる |
| **IX-07** | **ホバーの1行要約に、段階2以降の情報（根拠の全件・生データ・実値）を含めない** |
| **IX-08** | **ホバーの輪郭は「選択できる」ことの予告であって、「追跡できる」ことの約束ではない。** 輪郭が出てもクリック後に E-01 になることがある。この不一致は、PoC-03 の結果次第で解消を検討する（`03` 9章 未決定7） |

### 2.3 プレビュー上の選択の表現

> **プレビューはユーザーのアプリそのものであり、IDE の記号を描き込まない** (`02` 5.1 / 7.2節)。この制約下で「選択した対象が常に分かる」(原則3) をどう満たすか。

| 許可 | 禁止 |
| --- | --- |
| 選択要素の**枠**（1本の輪郭） | 値の吹き出し |
| プレビュー**外縁**（アプリの描画領域の外側）のステップバッジ ① | 要素の上に重なるバッジ |
| 選択要素が画面外にある場合の、端のインジケータ | 観測性バッジ・線種 |
| 選択枠に対応する色（他の面と同一色。UI-10） | 減光・マスク・加工（プレビューは現物であるため） |

> **参考画像が行っている「選択していないカードを減光する」表現は採用しない。** プレビューは「現物」という射影軸であり、IDE が減光・加工した時点でその軸の意味が失われる。上表の禁止列（減光・マスク・加工）は、**参考画像より優先する**。選択の表示は、選択要素の枠と、描画領域の外側に置くステップバッジだけで行う。

> **プレビューの内容を IDE が取り出して他の面へ運ぶときは、SEC 判定を通す** (`02` 7.2節)。選択要素のテキストを詳細パネルに載せる際に、規則マスクが適用される。

### 2.4 同期の原子性

| ID | 規約 | 理由 |
| --- | --- | --- |
| **IX-09** | **3面（A段階）の更新は原子的に行う。** プレビューだけ更新されてフロー図が前の選択のまま、という中間状態を作らない | 中間状態は「同期が壊れた」と読まれ、同期の仕掛け全体への信頼を失う |
| **IX-10** | **全面が揃うまで 500ms を超える場合は、骨格を先に出す。** ①詳細パネルにステップ数と種別の骨格 ②各ステップの中身を順に埋める。**空白のスピナーにしない** | UXR-30。空白は「情報が無い」と読まれる |
| **IX-11** | **面が選択対象を表現できない場合も同時に更新する**（空白にせず理由を出す） | UXR-07 |

### 2.5 面ごとの選択の表現（`02` 5.4節の表の操作への翻訳）

| 選択対象 | F-2 プレビュー | F-3 フロー図 | F-4 詳細パネル |
| --- | --- | --- | --- |
| `RenderedValue` / `DomElement` | **枠** | 起点ノードを強調 | 経路サマリ + 番号付きリスト |
| `Span` | 描画に寄与していれば**祖先の枠** + 「選択中の対象はこの中に含まれます」 | **ノードを強調** | ステップの概要 |
| `HttpExchange` | **「この面には対応する表示がありません」**（通信は画面上の位置を持たない） | ノードを強調 | ステップの概要 |
| `SqlStatement` | 同上 | ノードを強調 | SQL の概要（全文は生データタブ） |
| `DbColumn` | 祖先の枠（逆照合できた場合） | 終端ノードを強調 | カラム定義 |
| `LineageHop` | 対応表示なし | **線分を強調** | 推定の説明（`03a` UX-03） |

> **「対応する表示がありません」の文面を、面ごとに変えない** (IA変更案 P3-07)。面ごとに違う文面にすると、ユーザーは差分に意味があると読む。

## 3. 面の分担と同期

### 3.1 面が持つもの・持たないもの（UXR-26）

| 面 | 軸 | 持つ | **持たない** |
| --- | --- | --- | --- |
| F-2 プレビュー | 現物 | アプリの描画、選択枠 | 値の注釈、観測性の記号 |
| F-3 フロー図 | 空間 | ノードの種別・名称・状態・線種・バッジ | **属性値、SQL文、JSON、所要時間の個別値** |
| F-4 詳細パネル | 内容 | 経路サマリ、ステップの詳細、根拠、生データ | **全体の形** |
| F-5 ドロワー | 時間（B群）/ ネットワーク一覧（A群） | 通信の一覧と時刻 | 構造・内容 |

### 3.2 ステップバッジの運用

| 項目 | 規約 | 根拠 |
| --- | --- | --- |
| **性質** | **識別子ではない。** 現在のスコープ内の表示順序から再計算される揮発値 | `02` 5.3節 / IA変更案 #1 |
| 採番の順序 | 経路スコープ = 論理順（上流→下流）／ トレーススコープ = 開始時刻順（同時刻は深さ優先） | `02` 5.3節 |
| 集約ノード | 1つの番号を占める。展開時は `3-1`, `3-2` の枝番。**全体の再採番は行わない** | 同上 |
| 切断・終端 | **番号を与える**（「追跡できない」も1ステップとして数える）。欠番を作らない | 同上 |
| 色 | 3面で同一 (UI-10) |
| **再採番時** | **必ず通知する。** 「番号を振り直しました」を1行、3秒。操作を要求しない | `02` 12.5節 申し送り4 |
| 再採番が起きる操作 | スコープ変更（`page` ↔ `path`）、ページ切替、新しい実測への切り替え |
| 再採番が起きない操作 | 集約の展開/畳み、ズーム、パン、タブ切替、開示段階の変更、モード遷移 |

### 3.3 ホップを独立した線分として描く（A段階の描画モデル）

| 段階 | モデル | 理由 |
| --- | --- | --- |
| **A** | 経路を **ノードとホップの連なり**として描く。各ホップは独立した線分で、自身のレベルに従った線種を持つ | 「1本の線に単一のレベルを付ける」状況が発生しないため、OBS-09 と矛盾しない (`02d` 3.4) |
| B | 隣接する線分を1本の線として繋ぎ、区間ごとに線種を切り替える (OBS-12) | 同じ情報の精緻化 |

> **A段階で「1本の滑らかな線」を描かない**ことは、視覚的な洗練を犠牲にしているように見えるが、**経路内で確からしさが変わるという事実の、最も正直な表現**である。Phase 4 で「線を繋げたい」という判断が出た場合、それは OBS-12（B群）への前倒しであり、区間ごとの線種切替を同時に実装しなければならない。

## 4. 段階的開示

### 4.1 5段階（`02` 6.1節の操作への翻訳）

| 段階 | 操作 | 表示されるもの | **表示されないもの** |
| --- | --- | --- | --- |
| **0 未選択** | — | 種別アイコン・名称・状態・線種。俯瞰サマリ（件数・総時間・**推定を含む旨**） | 属性値、L0〜L3 のバッジ、生データ |
| **1 ホバー** | ポインタ | 1行要約 + 観測性の語 + ★ | 構造化された詳細 |
| **2 クリック** | 選択 | 経路サマリ（最上段）+ 番号付きリスト + 選択ステップの概要タブ | 生データ、根拠の全件、**実データ値**、秘密情報 |
| **3 詳細** | タブ切替 | ヘッダ / パラメータ / **根拠** / 生データ。**マスク解除と実データ開示はここ** | — |
| **4 参照** | 遷移 | テーブル詳細（S-06）。コードピークは**B群** | — |

### 4.2 段階0で表示してよいものの限定（UI-20 の遵守）

| 要素 | 段階0 |
| --- | --- |
| ノード | 種別アイコン、短いラベル、状態（正常 / 警告 / エラー / 不明）、線種 |
| エッジ | 線種（実線 / 破線 / 低彩度破線）、切断マーカー |
| 俯瞰サマリ | 「通信 N 件 / SQL N 件 / 総 Nms / **推定を含みます**」 |
| **出さないもの** | 属性値、所要時間の個別値、L0〜L3 の精密なバッジ、SQL断片、JSON |

> **段階0 の情報量は本設計の生命線である** (`02` 12.5節 申し送り1)。視覚デザインの段階で「余白が寂しいから値を1つ足す」判断が最も起きやすい。

### 4.3 戻る操作 — Esc の階段

> **Esc を押したときに何が起きるかが予測できることが、安心して深く潜れる条件である。**

```
段階3（タブを開いている / 開示している）
   ↓ Esc
段階2（選択している・概要タブ）
   ↓ Esc
段階0（選択なし・俯瞰）
   ↓ Esc
（何も起きない。モードは変わらない）
```

| ID | 規約 |
| --- | --- |
| **IX-12** | **Esc は1段階ずつ戻る。** 一気に初期状態へ戻さない |
| **IX-13** | **Esc でモードは変わらない。** モード遷移は Esc の対象外 |
| **IX-14** | **実データを開示している状態で Esc を押すと、開示が閉じる**（段階3 → 2 の一部として）。SG-05 |
| **IX-15** | **プレビューの背景クリックでは選択を解除しない。** プレビューはアプリの操作領域でもあるため、誤クリックで経路が消える体験を作らない。解除はフロー図の空白クリックか Esc |

## 5. 観測性の表現

### 5.1 常時表示される符号

| 符号 | 意味 | 色に依存するか |
| --- | --- | --- |
| **実線** | 実測（L0 / L1 / L1相当） | しない |
| **破線** | 推定（L2） | しない |
| **低彩度の破線** | 説明用の図（L3） | 彩度のみ。形でも区別する |
| **切断マーカー** | 追跡できなかった（`untraceable` / `unsupported` / `blocked-by-node`） | しない |
| **終端マーカー** | ここで正常に終わる（`static-literal`） | しない |
| **分岐の破線** | 複数候補（`multiple-candidates`）+ 候補件数 | しない |
| **★** | この経路でいちばん弱い箇所 | しない |

> **NFR-30（色のみで区別しない）を満たすため、一次符号を線種と形に置く。** 色は補助である。Phase 4 で色を決める際、色を一次符号に昇格させてはならない（低彩度変種 UI-08 が成立しなくなる）。

### 5.2 切断マーカーと「線を描かない」の違い

| | 切断マーカー | 線を描かない |
| --- | --- | --- |
| 意味 | 「追跡しようとしたが、できなかった」 | 「そもそも関係が無い」 |
| 使う場面 | `untraceable` / `unsupported` / `blocked-by-node` | 存在しないノード間（例：`rsc-direct` に通信ノードが無い） |
| 誤用の結果 | 線を描かないと「関係が無い」と読まれ、追跡の失敗が隠れる (OBS-05) | マーカーを置くと「失敗した」と読まれ、正常な構成が異常に見える |

### 5.3 縮退しても残す符号（`03` 5.4節）

| 残す | 消してよい |
| --- | --- |
| 切断マーカー / 終端マーカー | ラベルの文字列 |
| ★ | 所要時間の個別値 |
| 集約の件数 | アイコンの装飾 |
| 選択中の経路 | 非選択経路の細部 |

## 6. 参照と遷移

### 6.1 遷移の種類

| 種類 | 例 | モードが変わるか | 戻り導線 |
| --- | --- | --- | --- |
| **面内の移動** | ★ [ここを見る] → 該当ホップへ | 変わらない | 不要（同じ画面） |
| **モード内の遷移** | 俯瞰 → T4 | 変わらない | Esc |
| **モード間の遷移** | 終端カラム → データモード | **変わる** | **文脈帯 + [経路に戻る]** |
| **オーバーレイ**（B群） | コードピーク | 変わらない | Esc |

### 6.2 「押せるのに何も起きない」を作らない

| ID | 規約 |
| --- | --- |
| **IX-23** | **遷移先が存在しない場合、導線を出さない。** 無効化したボタンを置かない (`02b` 5.2節) |
| **IX-24** | **A群に存在しない機能への導線を置かない。** 「準備中」の席を置く基準は `03` 7.6節：①不在によって概念そのものが無いと誤解される場合のみ席を置く ②代替手段がある場合は置かない |

### 6.3 A群における `SourceLocation` の扱い

| 項目 | A群 | B群 |

## 7. キーボード

> NFR-32「主要操作はキーボードで実行可能であること」への回答。**具体的なキーの割り当ては Phase 4**（OS 慣習との整合のため）。本章は**どの操作がキーボードから到達可能でなければならないか**を定める。

| 操作カテゴリ | キーボードで到達可能であること | 備考 |
| --- | --- | --- |
| **モード切替** | 必須 | 探索 / データ / 実行 |
| **ページ切替** | 必須 | 一覧の上下移動 + 決定 |
| **プレビュー上の要素選択** | **必須** | Tab 順ではなく、**フロー図のノード移動と連動した選択**で代替する（プレビュー内の全DOM要素を Tab 順に並べるとアプリの Tab 順と衝突する） |
| **フロー図のノード・ホップ間の移動** | **必須** | 上流 / 下流 / 分岐の兄弟 |
| **番号付きリストの移動** | 必須 | 上下 |
| **ステップバッジによる直接移動** | 必須 | 番号の入力で該当ステップへ |
| **★ へのジャンプ** | **必須** | 最弱環への到達は最重要の1操作 |
| 詳細パネルのタブ移動 | 必須 | |
| ドロワーの開閉 | 必須 | |
| **Esc の階段**（4.3節） | 必須 | |
| 戻る / 進む | 必須 | |
| ズーム / 全体表示 | 必須 | |
| **実データ開示** | **キーボードから到達可能。ただしショートカット1発では実行させない** | 誤操作による開示を防ぐ |

| ID | 規約 |
| --- | --- |
| **IX-25** | **フォーカスの位置が常に見える。** キーボード操作時のフォーカスリングを省略しない |
| **IX-26** | **キーボードでの移動も3面を同期させる。** マウス操作と同じ同期規約が適用される |
| **IX-27** | **プレビュー内のアプリ自身のキーボード操作を奪わない。** プレビューにフォーカスがあるとき、IDE のショートカットは修飾キー付きのものに限る |

## 8. フィードバックの時間と種類

### 8.1 応答時間の階層

| 時間 | 扱い | 表示 |
| --- | --- | --- |
| **〜50ms** | 即時 | 何も出さない（結果だけ出る） |
| **50〜500ms** | 短い待ち | **何も出さない。** スピナーを出すとちらつきになる |
| **500ms〜2秒** | 待ち | **骨格を出して中身を埋める**（IX-10）。または進行表示 |
| **2秒〜** | 長い待ち | **段階名つきの進行表示** + [中止] |
| **10秒〜** | 異常の可能性 | 進行表示に「時間がかかっています」+ 想定される原因 + [中止] |

### 8.2 進行表示の規約

| ID | 規約 | 理由 |
| --- | --- | --- |
| **IX-28** | **段階名を出す。** 「読み込み中…」だけで10秒待たせない。「起動しています」→「ポート 3000 を待っています」→「ページを読み込んでいます」 | どの段階で止まったかが、次の行動を決める |
| **IX-29** | **進行中を空状態として描かない**（UXR-30）。「データがありません」と「まだ取りに行っている」を同じ見た目にしない | 最も頻出する誤読 |
| **IX-30** | **部分的に取得できたものは、揃うのを待たずに出す。** 構成検出では検出済みの項目を順次追加する | 待ち時間の体感を減らし、どこで止まったかを可視化する |
| **IX-31** | **[中止] は副作用を残さない。** 中止しても選択・既存の表示は壊れない | |

### 8.3 動かしてよいもの・いけないもの

| 動かしてよい | 動かしてはいけない |
| --- | --- |
| 選択時の強調の立ち上がり（短く） | **ステップバッジの番号**（再採番は瞬時に行い、アニメーションさせない） |
| フォーカス（減光）の切り替え | 経路のレイアウト（選択のたびにノードが動くと読めない） |
| パネルの開閉 | 進行中のノードの位置 |
| ドロワーの開閉 | **プレビューの内容**（アプリそのものであるため IDE は動かさない） |

> **レイアウトの安定性が、`02` 5.3節の「番号が動くと信頼を失う」と同じ理由で重要である。** 「③を見て」と口頭で共有している最中に ③ の位置が動くと、同期の仕掛けが機能しない。

## 9. 通知の使い分け

| 種類 | 使う場面 | 消え方 | 操作 |
| --- | --- | --- | --- |
| **インライン**（その場に出る） | 状態カード（E-01〜E-14）、実データ開示の説明、推定の説明 | 文脈が変わるまで残る | 0〜2個 |
| **1行通知**（トースト相当） | 「番号を振り直しました」 | **3秒で自動的に消える** | なし |
| **バナー**（上部に残る） | 「新しい実行結果があります [切り替える]」（E-14）、「実データ表示中 N 件 [すべて隠す]」（SG-05） | **自動では消えない。** 操作または文脈の変化で消える | 1個 |
| **モーダル** | **A群では使わない**（UXR-23） | — | — |

| ID | 規約 |
| --- | --- |
| **IX-32** | **操作が必要な通知は自動で消さない。** 自動で消える通知には操作を置かない |
| **IX-33** | **同じ通知を繰り返さない。** 同じ原因の状態カードが連続する場合、2回目以降は縮める（`03a` UX-04 A4） |
| **IX-34** | **通知でユーザーの操作を中断しない。** バナーはキャンバスを覆わず、押下を強制しない |
