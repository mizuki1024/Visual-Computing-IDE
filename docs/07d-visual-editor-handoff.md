### 3.2 扱いの規則

1. **F-01〜F-05 が閉じるまで、編集の書き込みを利用者が使える形で有効にしない。** 試作を製品のコードに入れる場合も、既定で無効・画面に出さない。
2. 閉じたことは、レビューの再現試験（`poc/edit/tests/review-repro.spec.mjs` の RV01〜RV08・RS02・RS04 に相当するもの）を**製品のコードに対して**、**題材の使い捨てのコピー**で回して確かめる（F-10）。PoC のコードで PASS しても閉じたことにしない。
3. 「探索側で F-01 を直した」ことは「編集が安全になった」ことを意味しない（`07c-f01-selection-revision-report.md` 第7節）。

### 3.3 F-01 と「自分が書いた変更」の設計論点

探索の規則では、選んだ要素のファイルの版が変わると選択は無効になる。編集の適用はまさにそのファイルを書くので、適用のたびに選択が消える。これを次のように扱う案を E2 で設計する（今回は決めない）。

* エンジンは書いたバイト列を知っているので、**適用後に期待される版**（内容の sha1）を計算できる。HMR の後の DOM の `data-vcide-rev` が期待値と一致し、かつ要素の内容の指紋が「書いた変更だけが違う」形で一致するときだけ、選択を新しい版へ**引き継ぐ**。
* 期待値と違う（外部変更が混ざった・別の要素が来た）なら、探索と同じく無効にして再選択を求める。推測で付け替えない。
* この引き継ぎは編集モードの中だけ。探索モードの照合（`resolveSelection` の7段）は変えない。

## 4. 最新の探索機能との統合方針

### 4.1 推奨する基準

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **A（推奨）** | 再開の時点で `feature/visual-editor` を `feature/explore` の先端へ**早送り**し、編集の作業はそこから続ける | 祖先関係なので必ず早送り（衝突 0・履歴の書き換えなし）。F-01 の版の照合・HMR の A1〜A5・観測の保持・試験の一覧の照合をすべて持った状態から始まる |

## 6. 最初に実装する最小機能: E1「安全なコード変更の基盤」

### 6.1 選んだ理由

1. **F-01〜F-05 はすべてこの層の問題**である（識別子と書き込み先・書き込み範囲・外部変更・ジャーナル・検証の契約）。この層が閉じないまま上の段を作ると、上の段の試験は安全でない基盤の上で通ることになる。
2. **利用者に見せない**ので、「F-01〜F-05 を未解決のまま製品の編集機能として有効化しない」を守ったまま着手できる。
3. PoC（`poc/edit/engine.cjs`）とレビューの再現試験がすでにあり、何を満たせばよいかが具体的（RV01〜RV08・RS02・RS04）。
4. E2〜E10 のすべてが、書き込みをこの1か所に通す前提になる（AI の変更案・コード生成も同じ照合を通す）。
5. FR-13〜16 を分割して利用者に出すことにならない（利用者向けの最初の機能は E4 で一体に出す）。

### 6.2 E1 の受入条件

| # | 条件 | 確かめ方 |
| --- | --- | --- |
| E1-1 | 書き込みは `src/server/edit/` の1つのモジュールだけが行い、既定で無効（環境変数などで明示したときだけ）。画面・API の利用者向けの入口を作らない | コードの検索（ほかに `fs.write*`・`rename` で対象のソースを書く箇所が無い）。既定の起動で書き込み API が 404 |
| E1-2 | **F-01**: 再解決・下書きの作成・適用の直前の3か所で、版（`data-vcide-rev`＝ファイルの版＝対応表の版）と内容の指紋を照合し、どちらかが合わなければ書かずに再選択を求める | RV07・RV08 相当の試験が製品のコードで期待どおり（同じ位置の別要素へ書かない） |
| E1-3 | **F-02**: 書き込み先の実体のパスが `realpath(root/src)` の中・許可した拡張子・リンクでない | RV01・RV02 相当（`next.config.mjs`・`.env` へのリンク）で書かずに拒否 |
| E1-4 | **F-03**: 初期範囲は1ファイル。複数ファイルの要求は拒否する（または各ファイルの直前の照合と書き戻しを実装し、窓を報告に明記） | RV04 相当で外部変更を上書きしない・`committed` と報告しない |
| E1-5 | **F-04**: 復旧は `applying` のジャーナルだけ。確定済みのジャーナルは復旧の対象にならない | RV05 相当で確定した変更が巻き戻らない |
| E1-6 | **F-05**: 検証の契約（必須の幅の集合・`predicted: false`・検証の時点の版・計測した文書と接続）をサーバーが自分で確かめる | RS02（1幅だけで通らない）・RS04（無関係なファイルの変更後に版を付け替えない）相当 |
| E1-7 | F-06（src/ に一時ファイルを残さない）・F-10（試験は使い捨てのコピーで）・F-11（書き込みの成否が不明なものを適用済みにしない） | 単体と、題材のコピーでの e2e |
| E1-8 | 探索の安全対策を変えない: `anchors.ts`・`previewProtocol.ts`・`dataAccess.ts`・注入を変えない（変えるなら探索側で先に） | `git diff feature/explore -- <探索の持ち物>` が空。`scripts/test-all.sh` の全件（探索の 37 本＋編集の新しい本）が失敗 0 |
| E1-9 | 新しい試験は `tests/` に置き、`scripts/test-all.sh` の一覧に足す | 一覧の両向きの照合が通る |
| E1-10 | 報告書に、保証する範囲と保証しない範囲（照合から rename までの窓・Tailwind 以外のスタイル・複数ファイル）を書く | 報告書 |

E1 の後は E2（同期）→ E3 → **E4 で初めて利用者に見せる**。
