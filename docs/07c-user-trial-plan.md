## 6. 未観測の理由の記録

### 6.1 方針

* **新しい計測機構は足さない。** 画面と既存の API がすでに「どの段で切れたか」と理由の符号を持っている（下表）。進行役はそれを書き写す。
* **自動の収集・送信はしない。** 参加者の操作・題材のデータ・画面の文字を、IDE が記録したり外部へ送ったりする機能は追加しない。記録は進行役が記録票に手で書くだけで、記録票はローカルに保管する。
* 題材の値（地名・連番）は架空の合成データなので書き写してよい。題材以外のデータが画面に出た場合は書き写さない。

### 6.2 段階と、画面・既存 API での見え方

| 切れた段階（ユーザーの言い方） | 画面に出る言葉 | 理由の符号（既存） | どこで読めるか |
| --- | --- | --- | --- |
| ① 要素のソース位置を特定できない | 右端「描画位置: 特定できません」／プレビューの選択の行 | 選択: `anchor-missing`・`injection-unavailable`・`anchor-not-in-manifest`・`id-mismatch`・`tag-mismatch`・`source-mismatch`・`outside-scope`・`unresolved`・`verifier-unavailable`（`src/lib/adapter.ts` 1659行付近） | 右端の理由・プレビューの要素の `data-sel-reason`。由来は `selection-unresolved` |
| ② 文書と通信を対応付けられない | 右端「切れた段階: 文書の同定」 | 由来: `document-unidentified`。詳細: `no-document-token`・`client-navigation`・`token-not-in-session`・`token-duplicated`・`path-mismatch`・`document-failed`・`refetched-after-document`・`exchange-evicted`・`history-evicted`（`src/lib/liveObservation.ts` `DOC_UNBOUND_LABEL`） | 右端の理由・`data-doc-binding`・`data-lineage-reason` |
| ③ SQL を観測できない | 右端「切れた段階: 実測との照合」・理由「…SQL を、この文書の通信で観測していません」／「サーバー処理・SQL に結べていません」 | `fetch-not-measured`・`no-server-link` | 右端の理由・`data-lineage-reason`・観測の一覧（「SQL 0 本」） |
| ④ SQL の呼び出し位置を確認できない | 右端「切れた段階: 実測との照合」・理由「呼び出し位置を確かめられません」／観測の SQL の行「特定していません — …」 | 由来: `fetch-site-unverified`・`fetch-callsite-unverifiable`。SQL ごとの詳細: `no-entry-callsite`・`no-callsite-record`・`no-app-frame`・`source-line-mismatch`・`component-not-agreed` ほか（`DATA_ACCESS_FAILURE_LABEL`） | 右端の理由・観測の一覧で通信を［表示］した SQL の行 |
| ⑤ 静的解析で値の参照先を特定できない | 右端「切れた段階: 静的解析」 | `no-value-site`・`mixed-text-children`・`multiple-value-sites`・`no-reference`・`multiple-fetch-sites`・`analyzer-unavailable` | 右端の理由・`data-lineage-reason` |
| ⑥ ソース更新により証拠が古くなった | 選択の行「コードが変更されたため…選択を解除しました」／右端「…ソースが書き換わったため…」 | 選択: `source-changed`・`manifest-stale`・`revision-missing`。由来: `source-changed-after-run`。SQL: `source-changed-after-call`・`build-changed-after-call` | プレビューの選択の行（`data-sel-cleared`）・右端の理由 |
| ⑦ HMR の安全判定で拒否された | 観測の SQL の行「特定していません — …HMR…／実行したコードは…古い版…／…処理中に…更新された」。右端は ④ と同じ「呼び出し位置を確かめられません」 | `hmr-evaluated-code`・`unrecognized-frame`・`frame-origin-unverified`・`request-start-unknown`・`changed-during-request`・`map-source-mismatch`・`map-source-unverified`・`executed-code-mismatch`・`executed-code-unverified`・`build-map-unbound`（A1〜A5。`CALLSITE_UNVERIFIABLE_REASONS`） | 観測の一覧の SQL の行。由来の符号は `fetch-callsite-unverifiable` |
| ⑧ SELECT 句に項目が無い | 右端「切れた段階: 実行SQLの SELECT 句」 | `no-column` | 右端の理由 |

* ④と⑦は右端では同じ符号（`fetch-callsite-unverifiable`）にまとまる。区別が要るときは、進行役が観測の一覧から同じ文書の通信を［表示］し、SQL の行の理由の文を書き写す。
* 符号を正確に取りたい場合（任意）: 進行役がブラウザの開発者ツールでプレビューの選択の行の `data-lineage-stage`・`data-lineage-reason`・`data-doc-binding` を読む。参加者の画面では行わない。
* 由来の評価の応答（`POST /api/runtime/lineage`）・観測の応答（`/api/runtime/observations`）は同じ符号を返す。IDE の画面と同じ入口の検査（同一オリジン・独自ヘッダ）があるため、記録のために外から呼ぶ道具は今回は作らない（第6.4節）。
