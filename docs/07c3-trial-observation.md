# 限定試用の観察項目（進行役・記録係用）

試用の手引き（`docs/07c3-trial-guide.md`）に沿って操作してもらう間に、**どの表示が分かりにくかったか**を記録するための項目です。1人あたり約 20 分＋聞き取り 10 分。

## 進め方の約束

* 参加者が詰まっても、**30 秒は口を出さない**。それでも進まなければ、手引きの該当の節を指すだけにする（操作を代わりにしない）。
* 「考えていることを声に出してください」と最初に1回だけ頼む。
* 正解を言わない。聞き取り（第3節）が終わるまで、表示の意味を説明しない。
* 記録は「何を見て」「何と言ったか／何をしたか」をそのまま書く。解釈は後で書く。

## 準備（進行役）

| 項目 | 確認 |
| --- | --- |
| 画面の大きさ | 1600×1000 以上（記録に実際の大きさを書く） |
| DB と IDE | 題材の DB（`poc/README.md`）・IDE（`npm run build && npx next start -p 3100`）が起動している。IDE は**参加者ごとに起動し直す**（前の人の検出結果を残さない） |
| 題材 | `poc/fixture-app`。パスを参加者に伝える |
| 記録 | 画面の録画（可能なら）と、この用紙 |

各項目に「○ 迷わず進んだ／△ 迷ったが自力で進んだ／× 助けが要った」と、その時の発言・行動を書く。

### 1. 開く・2. 起動する

| # | 観察すること | 分かりにくさの兆候 |

## 2. 記録しておく事実

* 手引きの各節にかかった時間（目安: 開く 1 分・起動 1 分・選ぶ 3 分・由来 5 分・未確認 5 分）
* 進行役が助けた回数と、その場所
* 声に出した語のうち、画面の語と違う言い換え（例:「推定」を「たぶん」と言った）
* 画面の幅・ブラウザ・ズーム倍率

## 3. 聞き取り（操作の後・10 分）

まず次の質問を**この順で**聞く。答えを誘導しない。

1. 地名「アオバ台」は、どこから来たと思いますか。どのくらい確かだと思いますか。（O-6・O-7 の確認）
2. 「表示用の固定ラベル」は、どこから来たと思いますか。（O-11・O-13 の確認。正答は「DB ではない／分からないと表示されていた」）
3. 「実測」「推定」「未確認」を、それぞれ自分の言葉で説明してください。
4. **いちばん分かりにくかった表示はどれですか。** 画面を指してください。（スクリーンショットに印を付けてもらう）
5. 読まずに飛ばした文はありましたか。それはなぜですか。
6. 図（中央）と文章（右端）のどちらを主に見ましたか。
7. 見本（合成デモ）を見ましたか。見た場合、自分の題材のデータと区別できましたか。
8. この道具を、どんな場面なら使ってみたいですか。使いたくない場面はありますか。

最後に、次の 5 段階で答えてもらう（1 = まったくそう思わない 〜 5 = とてもそう思う）。

| # | 文 |
| --- | --- |
| Q-1 | 選んだ値が「どこから来たか」が分かった |
| Q-2 | 確かめられたことと、推測したことの区別が分かった |
| Q-3 | 「未確認」と出たとき、何が分からないのかが分かった |
| Q-4 | 次に何をすればよいか、画面から分かった |
| Q-5 | 右端の文章の長さはちょうどよかった |

## 4. 結果のまとめ方

* O-1〜O-16 ごとに ○△× の数を集計し、× が 2 人以上の項目を「直す候補」とする。
* 聞き取り 2・3 で「実測」を「DB まで確かめた」と答えた人がいれば、P1-10 の表示（描画位置と値の由来の分け方）が不十分だったものとして記録する。
* 聞き取り 7 で合成デモを自分のデータと混同した人がいれば、P1-9 の表示が不十分だったものとして記録する。
* 7C-0 から持ち越した観察項目（右ドックの文の長さ・推定の札の読み取り）は O-7・O-9・O-14・Q-5 で確かめる。
