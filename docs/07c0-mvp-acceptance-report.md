**PoC 専用設定（対象プロジェクトへの変更）**: `next.config.ts` に 14 行を足した — IDE が起動したとき（`POC03_ANCHOR=1`）だけ、IDE の `poc/anchor/loader.cjs` を `*.tsx` の Turbopack ローダとして読む（ローダのパスは IDE の**絶対パス**）。IDE は対象の設定を書き換えないので、利用者が手で書く必要がある。

**由来が切れる原因（調べて分かったこと）**

1. **呼び出し位置の入口の計装が、対象プロジェクトの `pg` に掛からない（P1-1）。** `ide-instrumentation/otel.cjs` の `patchCallsiteEntry` は `require('pg')` / `require('pg-pool')` を計装の置き場所（`poc/fixture-app/`）から解決するため、**fixture の `pg` だけ**を包む。別のプロジェクトは自分の `node_modules/pg` を使うので、SQL のスパンは取れても入口のスタック（`entry`）は常に `null` になる。確認のため、解決元を対象プロジェクトにする変更を**一時的に**入れて1回だけ実行したところ、実測の段は通過した（変更は元に戻した。コミットしていない）。
2. **スキーマ修飾の無いテーブル名では列が決まらない（P1-2）。** 上の一時変更のもとで次の段に進むと、`FROM products` の SELECT 句の列は `resolved: null` になり、`no-reference` で切れた。fixture はすべて `poc.listings` と修飾しているので表に出なかった。しかも画面の理由は「静的解析で…参照の連鎖を解けません」で、**原因の段を取り違えて**いる（静的解析は `price` を `PriceTag` の props を通して取得まで正しく辿れている）。
3. **要素識別子の注入に手編集が要る（P1-3）**（上の PoC 専用設定）。

**実物の Codespaces は使えなかったため未検証。** 本段階のクラウド環境は Codespaces ではなく、ブラウザと IDE が同じコンテナにある。転送の挙動は既存の E2E の模擬（転送役）でだけ確かめている。

- **上限 200 件に達した後は、新しく読み込んだ文書が記録されず、選択は「文書を同定できません」で切れ続ける**（250 要求後・1,500 要求後とも `token-not-in-session`）。理由の文は「別の起動・停止の前の文書、またはまだ応答を送り終えていない」で、実際の原因（上限）を示さない（**P0-1**）。
- 画面は観測 API を 1.5 秒ごとに取りに行くので、上限に達すると約 **1.75 MB/秒**を受け取り・解析し続ける（P1-8）。
- 収集ファイルは 1 要求あたり約 47 KB 増え、**起動をまたいで削除されない**（本段階の終わりで `.ide-runtime/spans/` に 9 ファイル・74 MB）（P1-8）。

### 5.3 既存試験の資源

29 本を直列に回して合計 237 秒。最大は `queries-e2e` / `lineage-e2e` の 1.64 GB（IDE・開発サーバー・ブラウザを自分で起動する）。以前 Mac がメモリ不足で停止した件は、これらを並列に回すと 1 本あたり 1.3〜1.6 GB が重なる。**E2E は直列で回し、手元では 8 GB 以上の空きを確かめてから回す**ことを推奨する。

## 10. 限定試用へ進めるか

**P0-1 と P0-2 を直した後なら、題材を固定した案内つきの限定試用に進めてよい。**

- 中核の体験（値 → DB カラム、推定の明示、切れた理由、起動をまたいで混ざらないこと）は、題材の上で実ブラウザで成立した。
- P0-1 は中核の操作を、原因の分からない形で止める。P0-2 は中核の「図」を隠す。どちらも試用の早い段階で必ず当たる。
- 利用者自身のプロジェクトでの試用は、P1-1・P1-2・P1-3 が揃うまで進めない。揃わないと、DB カラムまで辿る経路は必ず切れる。理由は出るが、仮説（H-01）の検証にならない。
- 案内（試用の手引き）に書くこと: 起動後は「プロジェクトと実行」を閉じる（P0-2 を直すまで）。リンクで移った後は ↻ で読み込み直してから選ぶ（P1-7）。表示が合成デモに戻っても自分のデータではない（P1-9）。
