| 観測の鮮度（F 軸） | 一致（14:21 の起動で版 `7c2e` を観測）。**下書きは経路に含まない** |
| 編集可否（E 軸） | 条件付きで可能（`shared-definition`） |

### 4.1 U-01 適用前プレビューの見せ方

> **推奨: キャンバスの［表示: 現在のコード｜適用前プレビュー］を全アートボード共通の切替にし、見出しの斜線地と語で区別する。方式ごとに語だけを変え、形は変えない。**

| EP-12 の結果 | ［表示］の右側の語 | 見出しの語 | 枠の中 |
| --- | --- | --- | --- |
| 方式 A（予測の重ね合わせ） | 適用前プレビュー（予測） | ▨ 適用前プレビュー（予測）· 下書き N 件を反映 | 予測を重ねた描画 |
| 方式 B（隔離環境の実描画） | 適用前プレビュー（作業ツリーには未適用） | ▨ 適用前プレビュー（作業ツリーには未適用） | 別の作業コピーの描画 |
| 成立しない | 切替を置かない | 「現在のコード」だけ | 現在のコード。右ドックの「変更前 → 変更後」と S-14 の差分で判断 |

| 規則 | 内容 |
| --- | --- |
| 切替は全アートボード共通 | アートボードごとに由来が混ざると「どちらがいまのコードか」を比べられない |

### 4.2 U-02 「選択」と「ページを操作」

> **推奨: キャンバスの操作群の先頭に2つの区切りボタン［▸ 選択｜☝ ページを操作］を置く。既定は「選択」。ページを操作している間も、選択と右ドックは保つ。**

| 既定 | 選択（IX-E01: 編集モードのクリックは選択） |

| 適用前プレビュー（予測）との関係 | 予測の重ね合わせの上でページを操作すると、予測が実際の描画とずれうる。**方式 A のときは、ページを操作に入ると［表示］を現在のコードに切り替え、1行通知を出す**。選択に戻ると元の表示に戻す（EP-12 の結果で見直す） |

| 選択の行方 | 遷移先に同じ `JsxSite` があれば保ち、無ければ「最後に確認できた選択」（ED-06）を右ドックに残す |

### 4.3 U-03 既定で並べる幅

> **推奨: Desktop 1440×900 と Mobile 375×812 の2つ。追加の既定候補は 390・768・1024・1280。**

| 項目 | 推奨と理由 |
| --- | --- |
| 1440 | 一般的なノート PC の幅。Tailwind の既定では sm・md・lg・xl が効き、2xl（1536）は効かない。`02e`・`03e` の例と同じ値で、文書と画像の対応が取りやすい |
| 375 | 主要なスマホの中で狭い側。基本（variant なし）だけが効く幅として、**モバイルファーストの基本値を確かめる**のに向く。390 は追加の候補に置く |
| 境界の上に置かない | 既定・候補の幅を、プロジェクトのブレークポイント（EP-14 で読む）からちょうど 0〜8px の位置に置かない（640・768 などの真上だと、1px の差で効く指定が変わり、見たものと他の端末の結果が食い違う） |
| `03e` U-03 の「探索のプレビューに近い幅」 | **補正を提案**: 現在の探索のプレビューの幅は**パネルの幅で決まり、端末の幅ではない**（`02e` 1.5）。既定の幅の組には使わず、探索 → 編集の遷移で**主選択を置くアートボードを選ぶ**ときだけ使う（`02e` 5.8 の規則のまま）。`02f` C-15 に記録 |
| 1440 と 375 を同じ倍率で並べる | 50% で 720×450 と 188×406。キャンバス幅 992px に収まる |

## 5. S-14「変更の確認」— 役割と遷移（画面設計はしない）

| 項目 | 内容 |
| --- | --- |
| 役割 | **コードへ書き込む判断の唯一の場所**（`02e` 4.3）。変更案の一覧（由来: 利用者／AI／生成）、ファイル単位の差分と各差分の上の影響範囲の要約、適用前プレビューとの切替、検査、競合、適用・破棄、適用済みの履歴と適用の取り消し |
| 入口 | ①N0 の［変更を確認］②右ドック下部の［変更を確認］③競合・外部変更のバナー［競合を確かめる］④検査の状態カード EC-09 の［問題の箇所を見る］ |
| 出口 | ①［編集に戻る］→ S-11（選択・アートボード・下書きを復元）②［コードに適用］→ S-11 へ戻り、アートボードの見出しは「更新を待っています」→ 再描画 → 検査 ③［下書きを破棄］→ S-14 に留まり［破棄を取り消す］を出す |
| S-11 との分担 | S-11 は要素とプロパティの言葉（「余白 p-4 → p-5」）、S-14 はコードの言葉（ファイル差分）。**S-11 に適用ボタンを置かない**（UXR-E01） |
| 複数ファイルの適用 | 適用の結果をファイルごとに示せる構成にする（書いた／書いていない／書き戻した／書き戻せなかった）。「全ファイルか無か」が成立するかは EP-06（R-03）。成立前に「何も書き込んでいません」を約束する文言を置かない |
| 危険操作との関係 | S-14 の適用・破棄・取り消しは通常の編集フローで、確認ダイアログを置かない（R-04）。将来 S-14 に危険操作（ファイルの削除を伴う変更案など）が載る場合、NFR-23 の該当性を要件定義で判断する |
