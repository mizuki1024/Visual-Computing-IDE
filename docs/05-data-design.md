## 2. このプロダクト固有の設計 — 実在と設計案を取り違えさせない

### 2.1 なぜ必要か

本プロダクトは**観測**ツールであり、「いま何が分かっているか」を **実線＝実測 / 破線＝推定** で言い分けてきた（`03b` 5.1節）。
データ設計は**まだ無いもの**を扱うので、第3の状態が要る。

**参考画像は、すべての要素が同じ見た目である。**「このテーブルはもうDBにある」と「これは私の案」が区別できない。
観測性を価値の中心に置く本プロダクトでは、これは最も避けるべき混同である（`01` 0.2節 / OBS-05）。

### 2.2 符号

| 状態 | 枠 | 面 | 語 |
| --- | --- | --- | --- |
| **実在** — いまDBで確認できた | **実線** | 不透明 | 「実在」チップ |
| **設計案** — まだ無い。これから作る | **破線** | 半透明 | 「設計案」チップ |
| **関係** | 片方でも設計案なら**破線** | — | — |

NFR-30 のとおり**色は一次符号にしない**。枠の形（実線／破線）と語が一次で、色は要素の種別（人／モノ／できごと）を表す別の軸に使っている。

### 2.3 件数を正直に出す

本シナリオでDBに実在すると観測できたのは **`properties` だけ**である（`03a` UX-02 のトレースで `public.properties` を観測した）。
したがって画面上部に **「実在 1 ／ 設計案 5」** と出し、「いまDBで確認できたのは `properties` だけです」と明記した。
`02d` 2.3節の「件数は導出値であり定数ではない」に従い、要素を足すとこの数は増える。

## 3. 非エンジニアが考えられるようにするための3つの仕掛け

### 3.1 パレットの語彙を、DBの言葉にしない

「テーブル」「カラム」「外部キー」ではなく、**業務の言葉**を並べる。さらに**3つに分類**した。この分類がテーブル設計の判断そのものになる。

| 見出し | 要素 | なぜこの分類か |
| --- | --- | --- |
| **ずっとあるもの** | 人 ／ モノ | いわゆるマスタ。更新されるが消えない |
| **起きて記録されるもの** | できごと | いわゆるトランザクション。積み上がる |
| **要素に付けるもの** | 状態 ／ 情報項目 | 単独のテーブルにならないことが多い |

**「ずっとあるもの」と「起きて記録されるもの」を分けること自体が、テーブル分割の判断である。** 用語を教えずに、置き場所で学べるようにした。

### 3.2 関係を文章で書く

`会員 ─[1:N]→ 物件` ではなく、**「登録する（1人が複数の物件）」**と書く。
右パネルでも「**会員 が 物件 を 登録する**」という完全な文にしている。

### 3.3 業務モデルとテーブルを同時に見せる

下部の「テーブル設計プレビュー」は、**上の業務モデルをそのまま変換したもの**である。要素を選ぶと対応するテーブルが光る。
「人を1つ置いたら `members` テーブルが1つ増える」が、操作しなくても見える。
**これが「ER図作成ツールではない」ことの実体**であり、同時に第1章の決定2（構造を1つに保つ）の担保でもある。

## 4. 既存の規約との整合

| 要件 | 担保 |
| --- | --- |
| UI-01 / UI-02 彩度は意味の符号化にのみ | 色は**要素の種別**にのみ割り当て。装飾の色を足していない |
| NFR-30 色のみで区別しない | 実在／設計案は**枠の形**、種別は**アイコンの形**＋語。グレースケールでも判別できる |
| UI-05 余白 | 常時表示の文章を抑えた（4.1節） |
| UI-07 重複表示しない | 同じモデルを2か所に出すが、**上＝業務の言葉／下＝テーブルの言葉**で役割が違う。同じ語を2回言っていない |
| IX-23 / IX-24 押せるのに何も起きない導線を作らない | パレットの5つ、提案の「設計案に加える」、SQLの「コピー」は**すべて実際に動く** |
| UXR-12 肯定記号を使わない | 提案に「おすすめ」「ベストプラクティス」等を付けていない。**気づいた理由だけ**を添える（例：「『契約』があるため」） |
| `01` (a) 非改変（必須） | 生成は下書きまで。コピーのみ。画面に明記 |
| `02b` FR-70「AIをモードにしない」 | 提案はパレット内の一区画。モードにしていない |

### 4.1 常時表示の文章を減らした判断

関係の言葉（「登録する（1人が複数の物件）」等）を**全部出すとラベルが重なる**。
`04b` 3.1節で決めた「常時表示する文章を増やさない」と同じ方針で、**選んだ要素につながる関係だけ言葉を出す**ことにした。
他の関係は線だけ残す（消さない）。全件は右パネルの「関係」に常に出ている。
