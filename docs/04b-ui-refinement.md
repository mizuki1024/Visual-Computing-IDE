## 1. 課題 A — 経路の折り返し

### 1.1 原案で何が起きていたか

原案 A案のキャンバス座標で、⑦→③ の線は次を通っていた。

```
⑦(520,600) → 右へ x=580 → 下へ y=740 → 左へ x=30 → 上へ y=472 → 右へ ③(82,472)
```

| 問題 | 内容 |
| --- | --- |
| **1. 外周を一周する** | 右辺・下辺・左辺の3辺を使う。線の長さ **1044px**。キャンバス（620×820）の外周の約 6 割 |
| **2. 減光ノード群と重なる領域を通る** | 「選択していない経路」（y=648 前後）の真下・真横を通り、関心外の要素と最弱環の線が近接していた |
| **3. 往路にも逆行があった** | ③→④ が「右へ出て **172px 上へ戻って** また右へ」の折れ線。**戻り線の前に、往路の中にすでに逆行が1つあった** |

> **3 が最も重い。** `04a` は「外側（左→右）と内側（右→左の戻り）の方向が衝突する」と書いたが、実際には衝突は**往路の内部**でも起きていた。

### 1.2 3案に共通して入れた対応

| # | 対応 | 効果 |
| --- | --- | --- |
| **A-a** | **③ と ④ を同じ高さに置く。** ③→④ は水平な1本の線になる | **往路から上向きの区間が消えた（1本 → 0本）** |
| **A-b** | 戻り線を**下辺の専用レーン**に移し、立ち上がりを**ブラウザ帯の内側**に入れる | 右辺・上辺を通らなくなった。線の長さが短くなった（1044 → 868〜940px） |
| **A-c** | 減光ノード群を**戻りレーンより下**へ移す | 戻り線と関心外の要素が重ならなくなった |
| **A-d** | ⑤ の分岐を**共通の枝 → 分岐点（○）→ 2本**として描く | 「⑤ から2つに分かれる」ことが形で読める。原案は独立した2本の曲線で、分岐点が無かった |
| **A-e** | ③ の**入口の辺を分ける**（上辺で ②、左辺で ⑦ を受ける） | 合流が位置で区別できる。③ が「往路の出口」と「復路の入口」を兼ねることが読める |
| **A-f** | 折れ線を**直交＋角丸**に統一する | 折れの位置が読み取りやすい。曲線と折れ線の混在をやめた |
| **A-g** | 切断マーカーを**サーバー帯の内側を上へ抜ける**向きに変更 | 原案はデータベース帯へ向かっており、「DBへ行こうとして失敗した」と誤読されうる形だった。外部呼び出しは**層の外**へ出る |

### 1.3 消していないもの

| 項目 | 確認 |
| --- | --- |
| ⑦→③ の線 | **3案とも最後まで描いている。** 短縮も省略もしていない（`03a` UX-02：番号を振り直して見かけ上一直線にしてはならない） |
| ⑤→⑥ と ⑤→⑦ の2本 | 両方とも描いている。`02a` のモデルに無い **⑥→⑦ は描いていない**（OBS-05） |
| 切断マーカー | 1件。線を消さず ✕ で止めている |
| 減光した経路外ノード | 2ノード。削除していない（UI-33） |

## 2. 課題 B — ノードの情報量

### 2.1 ノード上に置くもの（3案共通）

| 置く | 置かない |
| --- | --- |
| 種別アイコン（線画7種） | 所要時間・行数・SQL断片・JSON |
| ステップバッジ（①〜⑦） | L0〜L3 のバッジ・確度ラベル |
| 短いラベル（種別名） | 属性値 |
| 識別名（A-3 は ① と ⑦ のみ） | 経路に対する肯定記号（✓・「検証済み」等） |
| **状態の記号（正常以外のみ）** | **正常の記号**（UXR-12：経路に対する肯定記号を使わない） |

> **状態の扱い**（補助図1 右）。正常・警告・エラー・不明の4状態のうち、**正常には記号を置かない**。
> 本モックの7ノードはすべて正常のため、3案とも状態の記号は出ていない。異常は**ホップ側**に1件あり、それは切断マーカーが表している。

### 2.2 A-3 だけが踏み込んだ点

A-3 は**中間ノードの識別名をキャンバスから外した**（`PropertyCard` / `GET /api/properties` / `properties` の3つ）。
残したのは **① の「千葉県」**（主張の起点）と **⑦ の `area`**（主張の終点）だけである。
外した3つは詳細パネルの番号付きリストに**そのまま残っている**（情報は失っていない）。

> **これは判断の分かれ目である。** 「経路の形を読む」だけなら識別名は不要だが、
> 「どの通信だったか」を図の上で確かめたい使い方では不便になる。**A-3 を選ぶかどうかは、この一点の判断に近い。**

### 2.3 帯見出しの扱い

`04a` が指摘した「帯見出しが 10px で初見では見落としうる」への対応。

| 案 | 対応 |
| --- | --- |
| A-1 / A-2 | 見出しを 10.5px・字間 2.6 に上げ、**見出しの下に水平の罫を1本**入れて「ここから下が帯の中身」を示した |
| A-3 | **罫線をやめ、帯を淡い面（`rgba(255,255,255,.021)`）にした。** 線を2本減らし、面で層を示す |

> いずれも**色を足していない**。A-3 の面は白の不透明度のみで、`04` 2.1節のトークンに新しい色を追加していない。

## 3. 課題 C — 説明の分かりやすさ

### 3.1 規則：キャンバスに語を残すのは「観測できていないこと」だけ

> C案の長所は「**何が観測できていないかを読むのに1操作も要らない**」ことだった（`04a` 2.6節）。
> 一方 C案の欠点は「キャンバス上の文字数が最多」だった。**この2つは両立できる** — 文字を減らす対象を、観測**できている**ほうに限ればよい。

| ホップ | 原案の常時表示 | 改善3案の常時表示 |
| --- | --- | --- |
| ①→② renders（実測） | 「この要素を描いたコンポーネント」2行 | **なし** |
| ②→③ derives（**推定**） | 「応答のどの項目が、この値になったか」2行 ＋ 推定チップ | **「推定」チップのみ** |
| ③→④ handles（実測） | 「その通信を受けたサーバーの処理」2行 | **なし** |
| ④→⑤ executes（実測） | 「その処理が実行したSQL」2行 | **なし** |
| ⑤→⑥ reads（実測） | 「そのSQLが読んだテーブル」2行 | **なし** |
| ⑤→⑦ projects（実測） | 「そのSQLが取り出した列」2行 | **なし** |
| ⑦→③ maps（**推定・最弱環**） | 「カラムと応答項目の対応づけ」＋ ★推定チップ | **そのまま維持** |
| 切断1件 | 「追跡できません／未対応の構成です」 | **そのまま維持**（UI-07 によりキャンバスのみ） |

結果、キャンバス上の文字ブロックは **36 → 24（A-1 / A-2）／ 21（A-3）** になった（ステップバッジを除く機械的な計数）。

> **この規則の効果**：キャンバスを眺めたとき、**文字が出ているところが、そのまま「怪しいところ」になる。**
> 原則6（見えないことを見えないと言う）と、UXR-13（経路の長さを確からしさに使わない）の両方に沿う。

### 3.2 外した説明はどこへ行ったか

**消していない。置き場所を変えただけである**（補助図1）。

| 段階 | 場所 | 本書で追加・変更したこと |
| --- | --- | --- |
| **0 未選択** | キャンバス | 変更なし（段階0の画面は本書の範囲外） |
| **1 ホバー** | ノードの脇の1行カード | **ホップの説明文の初出をここに置く。** 観測性の語（実測／推定）を必ず同じカードに載せる |
| **2 クリック（本モック）** | 右の詳細パネル | **番号付きリストの各ステップの間に、関係の説明を1行ずつ追加した**（下記） |
| **3 タブ切替** | 詳細パネル内 | 変更なし |

詳細パネルに追加した1行（3案共通）：

```
①  表示された値
 ├─ この値を描いたコンポーネント
②  コンポーネント
 ╎─ 応答のどの項目が、この値になったか（推定）     ← 破線のつなぎ
③  通信
 ├─ この通信を受けたサーバーの処理
④  サーバー処理
 ├─ その処理が実行したSQL
⑤  実行SQL
 ├─ ⑤ から分岐 — そのSQLが読んだテーブル
⑥  テーブル
 ├─ ⑤ から分岐 — そのSQLが取り出した列           ← 一直線ではないことを文で補う
⑦  カラム
★  ⑦→③ ここから ③ の応答へ戻ります（いちばん弱いところ）
```

| 判断 | 理由 |
| --- | --- |
| **⑥ と ⑦ の間に「⑤ から分岐」と書いた** | 番号付きリストは1〜7の一直線だが、**実際は ⑤ で分岐している**。リストの形が経路の形を偽らないようにするため |
| **末尾に戻りの行を置いた** | リストは ⑦ で終わるが、**経路は ⑦ で終わっていない**。★ブロックとは別に、**位置**（リストの末尾から ③ へ戻る）を示す |
| **つなぎ線の線種を合わせた** | ②→③ のつなぎだけ破線。キャンバスの線種と一致させた（UI-10 の精神） |

> **UXR-28（同じ事実を2か所で言わない）との関係**：キャンバスから実測5ホップの語を外したため、
> パネルの1行は**重複ではなく唯一の出現**になった。推定2ホップのみ、キャンバスに記号（チップ・★）、パネルに語、という分担になる。

## 5. 3案の設計

> **3案とも、扱う情報・観測性レベル・選択状態・画面サイズを統一している。**
> 違うのは**レイアウト**（ノードの配置・帯の表現・分割比率）と、**A-3 のみノード上の識別子の有無**である。

| 固定している条件 | 値 |
| --- | --- |
| 画面サイズ | 1600 × 1000 |

### 8.0 選定 — **A-2 を採用**（2026-10-31）

> 依頼者から選定を委任された（「おすすめで」）。判断の根拠を残す。

| # | 採用理由 |
