### 本書の重要性

> 本プロダクトの価値は「経路が見えること」ではなく、**「見えないことを、見えないと正しく言えること」**にある (`01` 0.2節)。
> したがって本書は補助文書ではなく、**中核体験の一部**である。取得できなかった状態の設計が甘いと、プロダクトは「正しそうに見える誤った図を出す装置」になる。

## 1. 状態カードの共通設計

### 1.1 4要素（UXR-16）

> **すべての状態カードは、次の4要素をこの順で持つ。** 省略してよいのは④のみ（解消手段が無い場合）。

| # | 要素 | 書き方 | 省略 |
| --- | --- | --- | --- |
| **①** | **何が起きたか**（事実） | 観測された事実のみ。断定できることだけを書く | 不可 |
| **②** | **なぜか**（理由） | 特定できた理由。**特定できない場合は「理由を特定できません」と書く**（推測で埋めない） | 不可 |
| **③** | **この結果わからないこと**（影響） | 「ここから先の◯◯は確認できません」 | **不可**（最も省略されやすく、最も重要） |
| **④** | **次にできること** | **0〜2個**。押せば実際に進むものだけ | 可（解消手段が無い場合） |

```
┌──────────────────────────────────────────┐
│ ① ここから先は追跡できませんでした          │
│                                          │
│ ② このサーバーはIDEの外で起動されています。  │
│    計装はIDEが起動したプロセスにのみ        │
│    適用されます。                          │
│                                          │
│ ③ サーバー内部の処理と、実行されたSQLは      │
│    確認できません。                        │
│    画面の要素・コンポーネント・ブラウザの     │
│    通信までは確認できています。             │
│                                          │
│ ④ [ IDEから起動し直す ]                    │
└──────────────────────────────────────────┘
```

### 1.2 共通規約

| ID | 規約 | 根拠 |
| --- | --- | --- |
| **ER-01** | **無反応を作らない。** 操作に対して必ず何かを返す | FR-11b |
| **ER-02** | **「エラーが発生しました」だけにしない。** 4要素を満たす | UXR-16 |
| **ER-03** | **理由を推測で埋めない。** 「おそらく」「〜と思われます」を使わない | UXR-18, OBS-05 |
| **ER-04** | **次の操作は最大2つ。** 3つ以上必要な状態は、原因の切り分けが足りていない | UXR-17 |
| **ER-05** | **解消できない場合、偽の選択肢を置かない。** 「打つ手がない」ことが正しい答えである | 原則7 |
| **ER-06** | **複数の原因が同時に成立する場合、上流の原因だけを出す。** 解消後に次の原因を出す | `03a` UX-04 A1 |
| **ER-07** | **取得できた範囲は必ず示す。** 「どこまでは分かっているか」が、ユーザーの次の判断を決める | NFR-12 |
| **ER-08** | **同じ原因が連続する場合、2回目以降はカードを縮める。** 「同じ理由です（計装されていません）」+ 既出の操作へのリンク | IX-33 |
| **ER-09** | **状態カードは選択を妨げない。** カードが出ていても、別の要素をクリックできる。「閉じる」操作を要求しない | 原則1 |

## 2. 状態カード一覧（E-01 〜 E-14）

### E-01. 要素を特定できない

> `SelectionFailure`。**FR-11b の実体。** 4つ（提案を含め5つ）の理由に分岐し、**理由ごとに次の操作が異なる**。

| 理由 | ① 事実 | ② 理由 | ③ 影響 | ④ 次にできること | 解消 |
| --- | --- | --- | --- | --- | --- |
| **`library-origin`**<br/>UIライブラリ由来 | 「この要素のコードの場所を特定できませんでした」 | 「この要素はUIライブラリの内部で作られています。追跡できるのは、あなたのコードが作った要素です」 | 「この要素そのものの出所は追えません。**ただし、この要素を含む親の要素なら追える場合があります**」 | **[ 親の要素を選ぶ ]** | △ |
| **`not-instrumented-build`**<br/>開発ビルドでない | 同上 | 「要素とコードの対応付けは、開発用のビルドでのみ使えます。現在は別の構成で動いています」 | 「画面のどの要素も、コードの場所を特定できません」 | [ 起動の仕方を見る ]（S-09） | ○ |
| **`anchor-missing`**<br/>要素に印が無い | 同上 | 「この要素には、ビルド時に付けるはずの印がありませんでした」 | 「この要素の出所は追えません。他の要素は追える場合があります」 | [ 対応範囲を見る ]（S-08） | ○ |
| **`unidentifiable`**<br/>特定できない | 同上 | **「理由を特定できません」** | 「この要素の出所は追えません」 | **なし** + [ この状況を記録する ] | × |
| **`measurement-not-started`**（提案 P3-05） | → **E-10 を参照** | | | | ○ |

| 設計判断 | 内容 |
| --- | --- |
| **選択は成立させる** | クリックした位置に枠を描く。「クリックが効いていない」と誤解させない（ST-18） |
| **[親の要素を選ぶ] が実質的な回復手段** | `01b` Q-03.2 C-3 により、ライブラリ由来の要素は一定の割合で発生する。親に自作コンポーネントがあることが多く、**1操作で上位へ上がれること**がこの状態の価値を決める |
| 事前予告は未決 | ホバー時に「この要素は特定できません」を予告するかは未決定（`03` 9章 未決定7）。PoC-03 でライブラリ由来要素の比率が判明してから決める |

### E-02. 計装されていない（`not-instrumented`）

> **INS-08 の実体。** IA変更案 #5 により `NodeStatus` の第5の値として追加された状態。

| # | 内容 |
| --- | --- |
| ① | 「ここから先は追跡できませんでした」 |
| ② | 「このサーバーはIDEの外で起動されています。計装はIDEが起動したプロセスにのみ適用されます」 |
| ③ | **「サーバー内部の処理と、実行されたSQLは確認できません。画面の要素・コンポーネント・ブラウザの通信までは確認できています」** |
| ④ | **[ IDEから起動し直す ]** |

| 設計判断 | 内容 |
| --- | --- |
| **「計装失敗」と書かない** | 失敗ではなく、適用条件を満たしていない。「失敗」と書くと、ユーザーは設定を疑って時間を失う (`02c` S-09) |
| **「SQLが0件」と書かない** | ST-05。これを混同すると「このページはDBを使っていない」という誤った結論に至る |
| **取得できた範囲を必ず書く**（③の後半） | ER-07。「何も見えない」のではなく「ここまでは見えている」 |
| 次の操作は1つに絞る | 解消手段が明確であるため、選択肢を増やさない |
| N0 との整合 | グローバルバーの計装インジケータが「適用不可」を表示している。カードと同じ理由・同じ操作を出す |

### E-03. SQLを取得できない

| # | 内容 |
| --- | --- |
| ① | 「サーバーの処理までは追跡できましたが、SQLは観測できませんでした」 |
| ② | 理由を特定できた場合のみ書く：<br/>・「使われているORMに対応していません（検出: XXX）」<br/>・「計装の一部が適用されていません」<br/>**特定できない場合：「理由を特定できません」** |
| ③ | 「どのテーブル・カラムから来たかは確認できません。**サーバーの処理までは確認できています**」 |
| ④ | [ 対応範囲を見る ] / [ 計装の状態を見る ] |

| 設計判断 | 内容 |
| --- | --- |
| **「DBを使っていない」と断定しない** | SQLが観測できないことと、DBアクセスが無いことは別である。③で「確認できません」と書き、「ありません」と書かない |
| 次の操作が2つある理由 | 原因が2系統（対応範囲 / 計装）あり、この時点で切り分けられない場合がある。**切り分けられる場合は1つに絞る**（ER-04 / ER-06） |

### E-04. DBに接続できない（`not-connected`）

| # | 内容 |
| --- | --- |
| ① | 「データベースに接続していません」 |
| ② | 「接続設定が見つかりません」／「接続に失敗しました（理由）」 |
| ③ | **「テーブルとカラムの定義、実際の値は確認できません。実行されたSQLは確認できており、そこからテーブル名は読み取れています（`properties`）」** |
| ④ | **[ 接続を設定する ]**（S-03） |

| 設計判断 | 内容 |
| --- | --- |
| **SQLから読めるテーブル名は出す** | ER-07。DB に繋がっていなくても、実測SQLの構文解析（L1相当）でテーブル名は分かる。**経路は完全には切れていない** |
| カラムまでは出さない | `SELECT` 句から列名を読める場合もあるが、**スキーマで裏取りできていない**。段階的に出す：SQL に列挙されていれば「SQLに書かれている列：area」と書き、「カラム `area`（型: text）」とは書かない |
| 「停止中」と書かない | ST-06。未接続と停止は別である |

### E-05. 複数の候補がある（`multiple-candidates`）

> **1つに断定しない**ことが最重要の状態。`01b` Q-04 C-4（同じ値が複数カラムに存在する）が誤答の主要因であり、ここで断定すると `NFR-17` の精神に反する。

| # | 内容 |
| --- | --- |
| ① | **「候補が 2 件あります。1つに絞れませんでした」** |
| ② | 「値が一致するカラムが複数あり、どれか1つに決められませんでした」 |
| ③ | 「出所はこの2つのどちらかです。**どちらかは確定できません**」 |
| ④ | [ 候補を比べる ] |

#### 候補の提示

```
候補 1  properties.area
        根拠 2 件：実行されたSQLの解析 ／ 値の一致
        ● この経路の実行時に、このSQLが実際に実行されました

候補 2  regions.name
        根拠 1 件：値の一致
        （値の一致だけでは1つに絞れません）
```

| 設計判断 | 内容 |
| --- | --- |
| **自動で1つを選ばない** | `02` 4.5節の主経路決定規則：①実測ホップを優先 ②証拠数が多い候補を優先 ③**同率なら決定せず `ambiguous` とする**。①②で決まらないときに1つを選んで断定してはならない |
| **実トレースで通った候補を強調する** | 「● この経路の実行時に、このSQLが実際に実行されました」。これは実測の事実であり、確度ラベルではない |
| **根拠の件数を候補ごとに出す** | ユーザー自身が判断できるようにする。IDE が判断を代行しない |
| 「値の一致」には但し書き | `02d` 1.3節の禁止事項 |
| 経路サマリでは主張を出さない | ST-10。`LineagePath.状態 = ambiguous` のときは「出所はこれです」と書かない |

### E-06. 静的な値である（`static-literal`）

> **これは失敗ではない。** 経路は `complete` であり、答えが出ている。

| # | 内容 |
| --- | --- |
| ① | **「この文字はコードに直接書かれています」** |
| ② | 「データベースや通信から来た値ではありません」 |
| ③ | — （わからないことが無い。**③を省略してよい唯一の状態**） |
| ④ | **なし**（答えが出ている） |

```
この値の出所
  コードに直接書かれています

  src/components/PropertyCard.tsx:48
```

| 設計判断 | 内容 |
| --- | --- |
| **エラーの見た目にしない** | 切断マーカーではなく**終端マーカー**を使う（`03b` 5.2節）。線は正常に終わっている |
| ★ブロックを出さない | 推定が存在しないため（`03` 3.6節） |
| 編集への導線を出さない | 編集は B群。A群では「押せるのに何も起きない」導線になる（IX-24） |
| コード位置はリンクにしない | A群では `SourceLocation` を表示するがリンク化しない（`03b` 6.3節） |

### E-07. 未対応の構成である（`unsupported`）

| # | 内容 |
| --- | --- |
| ① | 「ここから先は追跡できません」 |
| ② | **「この構成に対応していません（ORM: XXX）」** |
| ③ | 「SQLとテーブル・カラムは確認できません。**サーバーの処理までは確認できています**」 |
| ④ | **[ 対応範囲を見る ]**（S-08） |

| 設計判断 | 内容 |
| --- | --- |
| **検出した構成名を具体的に書く** | 「未対応です」だけでは、ユーザーは何が未対応か分からない |
| **プロジェクトを開いた時点で既に宣言されている** | S-02 で先に提示している (FR-07)。ここで初めて知ることにならないようにする |
| 「今後対応予定」と書かない | 約束できないことを書かない |
| 次の操作は情報提供のみ | 解消手段が無いため、解消を約束する操作を置かない（ER-05） |

| # | 内容 |

### E-10. 計測を始める前の読み込み（本書で追加・IA変更案 P3-05）

> **`03` 7.2節で発見した欠落。** プレビューが開かれる前に読み込まれた画面（外部ブラウザで先に開いていた、プレビューを後から接続した等）の要素をクリックした場合。

| # | 内容 |
| --- | --- |
| ① | 「この表示は、計測を始める前に読み込まれたものです」 |
| ② | 「このIDEが観測できるのは、接続した後に起きた通信と処理です」 |
| ③ | 「いま画面に出ている値について、実行時の情報は取得できていません。**コードから推定した経路は表示できます**」 |
| ④ | **[ 再読み込みして計測する ]** |

| 設計判断 | 内容 |
| --- | --- |
| **`not-traced`（静的のみ）と区別する理由** | 静的のみは「サーバーが動いていない」状態であり、起動が解消手段。E-10 は「サーバーは動いているが、この表示の時点を見ていない」状態であり、**再読み込みが解消手段**。同じ表示にすると、ユーザーは「このプロジェクトは計装できない」と誤解する |
| **`unidentifiable` に丸めない理由** | 丸めると「理由を特定できません」になり、1操作で解決する状況で手が止まる |
| 再読み込みの副作用 | アプリの状態（フォーム入力など）が失われる可能性がある。**ボタンの下に1行**：「ページを読み込み直します。入力中の内容は失われます」。モーダルにはしない（UXR-24） |

### E-11. 実測なし・静的解析のみ（`not-traced`）

> UC-01 代替フロー A3 の実体。**経路は表示する。** 表示しないのは実際の値だけである。

| # | 内容 |
| --- | --- |
| ① | 「実行していないため、コードから推定した経路です」 |
| ② | 「開発サーバーが起動していません」 |
| ③ | **「この経路は全体が推定です。実際に通ったかどうかは確認していません。実際の値は表示できません」** |
| ④ | **[ 開始する ]** |

| 設計判断 | 内容 |
| --- | --- |
| **経路を表示する** | `01c` M2 達成条件8「計装が失敗した状態でも、静的解析ベースの経路が『推定』として表示され、クラッシュしない」 |
| **★ を使わない** | 全体が推定であり、1箇所を名指しできない（`03a` UX-03 A2） |
| **実際の値を表示しない** | UC-01 代替A3。実行していない以上、値は存在しない |
| 線はすべて破線 | 全ホップ L2 |

### E-13. 値が加工されている（`untraceable`）

| # | 内容 |
| --- | --- |
| ① | 「この値は加工されています」 |
| ② | 「表示される前に、計算・連結・整形のいずれかが行われています」+ 検出できた場合はコード位置 |
| ③ | **「元になったカラムを特定できません。加工される前のデータがどこから来たかは追えません」** |
| ④ | **なし** |

| 設計判断 | 内容 |
| --- | --- |
| **部分的な候補を出さない** | 「おそらく `created_at` を整形したもの」のような推測を出さない（ER-03）。`01b` Q-04 C-3 により、加工があると値照合も静的解析も破綻する |
| 加工の種別は書く | 「計算 / 連結 / 整形」のどれかが分かれば書く。分からなければ「加工されています」のみ |
| 次の操作を置かない | 構造的な限界であり、打つ手が無い（ER-05） |

### E-14. 新しい実測が到着した（`stale`）

> **エラーではないが、黙って更新してはならない状態。**

| 形式 | **バナー**（カードではない） |
| --- | --- |
| 文面 | 「新しい実行結果があります」 |
| 操作 | **[ 切り替える ]** |
| 消え方 | 操作するか、選択を変えるまで**自動では消えない** |
| 現在の表示 | **保持する。黙って入れ替えない** |

| 設計判断 | 内容 |
| --- | --- |
| **黙って更新しない理由** | ユーザーが経路を読んでいる最中に内容が入れ替わると、読んでいた内容と手元の結論が食い違う。**これは本プロダクトが解決しようとしている問題（頭の中のモデルと実行時の事実の不一致）を、ツール自身が生み出すことになる** (`02` 5.5節) |
| UXR-29 との関係 | これは「背景で変わった事実」であり、通知して手動で切り替える。「ユーザーが要求した結果の到着」（解析完了による補完など）は自動反映する |
| 切り替えたとき | バッジが振り直される → **「番号を振り直しました」の1行通知**も出る |

## 3. 切断の表現規約

| 状況 | 表現 | 誤用した場合に起きること |
| --- | --- | --- |
| 追跡を試みたが失敗した | **切断マーカー** | 線を描かないと「関係が無い」と読まれ、失敗が隠れる |
| そもそもノードが存在しない（`rsc-direct` の通信ノード） | **何も描かない** | 切断マーカーを置くと「失敗した」と読まれ、正常な構成が異常に見える |
| 正常に終端した（静的リテラル） | **終端マーカー** | 切断マーカーを置くと失敗に見える |
| 上流が取得できず先に進めない | 切断マーカー + **上流の状態と解消操作** | ホップ側の問題として表示すると、原因の所在を誤らせる（ST-08） |

| ID | 規約 |
| --- | --- |
| **ER-10** | **切断マーカーは縮退・ズームアウトの対象外**（`03` 5.4節）。ズームアウトで切断が消えると「繋がっている図」に見える |
| **ER-11** | **集約ノードの中に切断がある場合、集約ノード自体に切断マーカーを付ける**（`03a` UX-06 A3） |

## 4. 空状態（データが無いこと自体が答えである場合）

> **エラーではない空状態。** 混同されやすいため別章として定義する。

| 状況 | 表示 | 禁止 |
| --- | --- | --- |
| **SQLの結果が0行** | **「0 件」**（`no-data`） | 空白、「データがありません」（取得失敗と混同される） |
| **このページで通信が発生しなかった** | 「このページの読み込みで、ブラウザからの通信はありませんでした」 | 空のフロー図 |
| **選択した経路に通信が無い**（`rsc-direct`） | ドロワーのネットワーク一覧に「この経路にはブラウザからの通信がありません」 | 空のリスト |
| **テーブルに行が無い** | 「0 行」 | 空白 |
| **検出できた利用箇所が0件**（B群） | 「検出できた利用箇所は 0 件です。**検出漏れが起きる条件があります**」 | 「利用されていません」（網羅性を保証できない。OBS-07） |

| ID | 規約 |
| --- | --- |
| **ER-12** | **0件を空白で表さない。** 「0」という数値を明示する |
| **ER-13** | **0件を「存在しない」と断定しない。** 観測できた範囲での0件である |

## 5. 面が選択対象を表現できない場合（UXR-07）

> `02` 5.4節「`no` のときに面を空白にしない」の文言化。

| 面 | 表現できない例 | 表示 |
| --- | --- | --- |
| F-2 プレビュー | `HttpExchange` / `SqlStatement` を選択した | **「この面には対応する表示がありません」**（通信やSQLは画面上の位置を持たない） |
| F-2 プレビュー | `Span` を選択し、描画に寄与している | 祖先の枠 + **「選択中の対象はこの中に含まれます」** |
| F-3 フロー図 | — | （A段階で表現できない選択対象は無い） |
| F-5 ドロワー | `rsc-direct` の経路を選択した | 「この経路にはブラウザからの通信がありません」 |

| ID | 規約 |
| --- | --- |
| **ER-14** | **面ごとに文面を変えない**（IA変更案 P3-07）。違う文面にすると、ユーザーは差分に意味があると読む |
| **ER-15** | **「選択がない（格納）」と「選択はあるが表現できない（説明文）」を区別する**（ST-16） |

## 6. 文言の禁止リスト（再掲と拡張）

| 禁止 | 理由 | 代わりに |
| --- | --- | --- |
| 「エラーが発生しました」のみ | 次の行動が分からない | 4要素のカード |
| 「データがありません」（取得失敗時） | `no-data` と混同される | 状態ごとの文言 |
| 「おそらく」「〜と思われます」 | 推測をシステムの断定として出す | 「推定しています」+ 根拠、または「特定できません」 |
| 「計装に失敗しました」（外部起動時） | 失敗ではなく適用条件を満たしていない | 「計装はIDEが起動したプロセスにのみ適用されます」 |
| 「このページはDBを使っていません」 | 観測できないことと、存在しないことの混同 | 「SQLは観測できませんでした」 |
| 「利用されていません」（逆方向トレース・B群） | 網羅性を保証できない | 「検出できた利用箇所は 0 件です」 |
| 「今後対応予定です」 | 約束できない | 「この構成には対応していません」 |
| 「すべて表示」 | 安全上の単位を崩す | **提供しない**（IX-19） |
| 「確度: 高 / 中 / 低」 | 較正されていない (NFR-17) | 「推定」+ 根拠の種別と件数 |
| 「完全に特定しました」 | 終端は構造的に L2 | 「推定しています」 |
| 「正常に完了しました」（経路に対して） | 同上 | 経路の状態を記号なしで表示 |
