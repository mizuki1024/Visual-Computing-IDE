## 1. 共通の比較シナリオ

> **3案は同一のデータ・同一の操作状態を描く。** 案の違いが構成の違いだけに由来するようにするためである。

### 1.1 合成データであることの明示

本シナリオの経路・SQL・所要時間・件数は、**UI 検討のために作った合成データ**である。実測した情報ではない。
モックアップの下部ドロワー右端に、その旨を常時表示している（スクリーンショットが単独で出回っても誤解されないため）。

### 1.2 操作状態

| 項目 | 値 |
| --- | --- |
| モード | 探索（N1） |
| ページ | `/properties`（物件一覧） |
| 選択対象 | プレビュー内 PropertyCard の表示値「千葉県」（`RenderedValue`） |
| スコープ | `path`（T4・単一経路） |
| 開示段階 | **段階2**（クリック直後）。段階3のタブは「概要」。実データ開示なし |
| 文脈帯 | **出さない**（探索モードで詳細パネルが開いているため。UXR-27） |

### 1.3 経路（7ノード・7ホップ）

```
① 表示された値「千葉県」
    │  renders  ── 実測（ビルド時の印）
② コンポーネント PropertyCard
    ╎  derives  ── 推定（応答のどの項目が、この値になったか）
③ 通信 GET /api/properties
    │  handles  ── 実測
④ サーバー処理（API Route）
    │  executes ── 実測
⑤ 実行SQL
    ├─ reads    ── 実測（実行されたSQLの構文解析）      → ⑥ テーブル properties
    └─ projects ── 実測（列を明示した SELECT のため特定できる） → ⑦ カラム area
                                                        ╎
                      maps ★ ── 推定（カラムと応答項目の対応づけ）→ ③ へ戻る
```

> **⑤ で2本に分岐する。** `reads` は `SqlStatement → DbTable`、`projects` は `SqlStatement → DbColumn` である (`02a` 3.5節)。**⑥→⑦（テーブルからカラム）の線はモデルに存在しないため描いていない** (OBS-05)。

| 項目 | 値 |
| --- | --- |
| 構成要素 | **14 か所**（ノード7 + ホップ7） |
| 実測 | 12 か所 |
| 推定 | **2 か所**（`derives` / `maps`） |
| 経路の観測性 | **推定**（最弱環に合わせる。OBS-10） |
| 最弱環 | **`maps`（⑦→③）**。同率の `derives` より下流にあるため（`02d` 2.2節の優先順位3） |
| 件数の扱い | 14 / 12 / 2 は**この経路から算出した導出値**であり、定数ではない（`02d` 2.3節） |

> **⑦→③ が経路の中で逆行する**ことは隠さない。`03a` UX-02 の「番号を振り直して見かけ上一直線にしてはならない」に従い、3案とも折り返す線として描いている。

### 1.4 異常状態（1件・3案共通）

| 項目 | 内容 |
| --- | --- |
| 事象 | ④ サーバー処理からの外部サービス呼び出しが追跡できない |
| 種別 | `LinkStatus = unsupported` → **切断マーカー**（E-07） |
| キャンバス上の表現 | 線を消さず、✕ 付きの切断マーカーで止める。「追跡できません／未対応の構成です」 |
| N0 との整合 | グローバルバーの対応範囲インジケータが「部分対応・1件」を表示している |
| 経路への影響 | **無い。** 選択中の経路（①〜⑦）は成立しており、切断は経路外の枝である |

### 1.5 経路外の表示（3案共通）

選択により T4（単一経路）に入っても、**このページの他の経路を削除しない**（UI-33・フォーカスモード）。
`GET /api/favorites` とその SQL の 2 ノードを減光して残し、「選択していない経路」と明示している。

## 2. 視覚言語（3案共通のデザイントークン）

### 2.1 色

> **UI-01（黒〜濃灰を基調）／ UI-02（彩度の高い色は意味の符号化にのみ）／ NFR-30（色のみで区別しない）を前提に組んでいる。**

| 役割 | 値 | 使う場所 |
| --- | --- | --- |
| 背景（最背面） | `#06070a` | アプリ地 |
| シェル | `#0a0c11` | モードタブの帯 |
| パネル面 | `#0f1218` | 各ペイン |
| パネル内の面 | `#131722` | 入力・チップ |
| 沈んだ面 | `#0b0e14` | プレビュー外枠・根拠ボックス |
| 境界 | `#1c2130` / `#161a25` | 1px の罫 |
| 主文字 / 副 / 第三 / 最弱 | `#e4e8f0` / `#98a1b4` / `#646d80` / `#454d5d` | 4段の文字階調 |
| **ラベンダー（選択）** | `#9d93e0` | 選択中の対象・ステップバッジ・★ |
| **ブルー（実測の線）** | `#8aa4cc` | 実線のホップ |
| **薄紫（推定の線）** | `#9a8fc4` | 破線のホップ |
| **グリーン（正常）** | `#78b79a` | 実行中・計装有効の状態ドット |
| **アンバー（注意）** | `#c2a06e` | 対応範囲インジケータ・切断マーカー |

| 規則 | 内容 |
| --- | --- |
| 彩度 | いずれも彩度を落としている。参考画像 `04`（低彩度変種）が成立する前提（UI-08） |
| 発光 | **選択中の経路のノードにのみ**、ごく弱い内側の輪郭を与える。常時発光させない（UI-03） |
| 色の一貫 | ステップバッジはプレビュー・フロー図・詳細パネルで同一色（UI-10） |
| **色を一次符号にしない** | 実測／推定の区別は**線種（実線／破線）と語（「推定」）**が一次。色は補助（NFR-30 / `03` 10.4 申し送り3） |

### 2.2 形と線

| 符号 | 形 | 意味 |
| --- | --- | --- |
| 実線 + 矢尻 | — | 実測（L0 / L1 / L1相当） |
| 破線 + 矢尻 + 「推定」チップ | ╎ | 推定（L2） |
| ★ 付きの「推定」チップ | ★ | この経路でいちばん弱い箇所 |
| 縦バー + ✕ | ⊦✕ | **切断マーカー**（追跡しようとしたができなかった） |
| 減光したノードと線 | — | 選択していない経路（削除ではない） |

> **ホップは独立した線分として描いている**（`03b` 3.3節）。隣接するホップを1本の連続線に繋いでいない。A段階で「1本の線に単一のレベルを付ける」状況を作らないためである。OBS-12（区間ごとの線種切替）は B群であり、前倒ししていない。

### 2.3 ノード

| 項目 | 内容 |
| --- | --- |
| 形 | 角丸の正方形（半径 = 辺の 26%）。内側にもう1本の細い輪郭 |
| アイコン | 線画のみ。7種（表示値 / コンポーネント / 通信 / サーバー / SQL / テーブル / カラム）。塗りは使わない（UI-04） |
| サイズ | A案 52px ／ B案 40px ／ C案 60px |
| **ノード上に置くもの** | 種別アイコン・ステップバッジ・短いラベル（種別名）・識別名のみ |
| **ノード上に置かないもの** | **所要時間・行数・SQL断片・JSON・L0〜L3 のバッジ**（UI-15 / UI-20 / `03b` 4.2節） |

> 参考画像 `03` / `04` はノードの脇に SQL 文や応答 JSON の抜粋を並べているが、**採用しなかった**。属性値は詳細パネルの担当である（UI-07 / UXR-26）。所要時間（124ms / 98ms / 42ms）は詳細パネルの番号付きリストにのみ置いている。

### 2.4 文字と余白

| 項目 | 値 |
| --- | --- |
| 和文 | Hiragino Sans / Noto Sans JP。`font-feature-settings: "palt"` |
| 等幅 | 識別子・パス・SQL・URL にのみ使用（コードと値であることを形で示す） |
| 文字サイズ | 9.5 / 10 / 10.5 / 11 / 11.5 / 12.5 / 16.5px の7段 |
| ペイン間の間隔 | 10px。ペインのヘッダ高 34px |
| **余白の方針** | 情報密度を上げるために余白を削らない（UI-05）。キャンバスの外周は最低 20px、ノード間は最低 90px |

| 階層 | 領域 | 本モックでの内容 |

### 3.1 詳細パネルの構造は3案で共通にした

`03` 10.3節は「経路サマリを詳細パネル最上段から移動する決定」を**進行してはならない条件**に挙げている。
したがって詳細パネルの構造（主張 → 二値の語 → 件数と最弱環の原則 → ★ブロック → 番号付きリスト）は**案の変数ではない**。
3案で変わるのはパネルの**幅と密度**、および**ホップの説明文をキャンバスとパネルのどちらに置くか**である。

### 3.2 経路サマリの文言（3案共通・`03` 3.5節のまま）

```
この値の出所
  properties . area  ［推定］

  14 か所のうち 2 か所が推定です。経路全体は、
  いちばん弱いところに合わせて「推定」になります。

  実測＝実際に起きたことを観測できた箇所。
  推定＝コードの形から推測した箇所。

★ いちばん弱いところ
  ⑦→③ カラムと応答項目の対応づけ
  ORMの内部変換は観測できません。別名や加工があると成立しません。
  根拠 2 件：実行されたSQLの解析 ／ 値の一致
  （値の一致だけでは1つに絞れません）
  ［ ここを見る ］
```

## 5. 3案の設計

### 5.1 A案 — Data Flow First

| 項目 | 内容 |
| --- | --- |
| 狙い | **経路の形そのものを主役にする。** 「どこを通ったか」を図として一目で掴ませる |
| 分割 | ページ 160 ／ プレビュー 410 ／ **キャンバス 622** ／ 詳細 360（プレビュー:キャンバス ≒ 1:1.5。Q-11 の回答どおり） |
| キャンバス | ブラウザ／サーバー／データベースの3帯を**左→右**に配置（UI-30）。ノード52px |
| ホップの説明 | **キャンバス上に小さく常時表示**（10.5px） |
| ⑦→③ の扱い | キャンバス下辺を回り込む大きな折り返しとして描く。★「推定」チップを線上に置く |
| 詳細パネル | 360px。経路サマリ + ★ + 7ステップ + 選択ステップの概要タブ |

**この案が賭けているもの**: 経路は「縦に並んだ7行」ではなく**層をまたぐ移動**である。層（ブラウザ / サーバー / DB）を空間として示せば、「どこで切れたか」「どこが推定か」が位置で分かる。

### 5.2 B案 — Preview First

| 項目 | 内容 |
| --- | --- |
| 狙い | **起点である現物を主役にする。** 選んだ後に視線を右へ送る |
| 分割 | ページ 150 ／ **プレビュー 680** ／ 経路ストリップ 320 ／ 詳細 400 |
| キャンバス | 縦1列の細いストリップ。ノード40px、ラベルは右 |
| ホップの説明 | **キャンバスからは外し、詳細パネルの各ステップの上に1行で置く**（「この要素を描いたコンポーネント（実測）」等） |
| ⑦→③ の扱い | ストリップ左端の細い折り返し線。★ と「推定」のみを置き、文章は詳細パネルへ |
| 詳細パネル | 400px。**7ステップそれぞれに関係の説明が付く**ため、パネル単独で経路が読める |

**この案が賭けているもの**: UC-01 の起点はプレビューのクリックである。プレビューが大きいほど「選べる」実感が強く、要素の取り違えも減る。経路は**索引**であって、読むのは言葉のほう。

### 5.3 C案 — Comprehension First

| 項目 | 内容 |
| --- | --- |
