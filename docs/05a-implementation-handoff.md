## 1. 【要判断】どちらを「確定画像」とするか

Phase 5A のプロンプトは「ダークな宇宙空間のような背景」「立体的なPC・サーバー・DBなどのノード」「ミニマップ」「キャンバス操作」と書いている。
**これは Physical View の記述である。** しかし探索画面として選定を行ったのは **A-2（平面）** であり、両者は別物である。

| | **候補A：A-2（平面の観測キャンバス）** | **候補B：Physical View（立体表示）** |
| --- | --- | --- |
| 画像 | `docs/04b-ui-mockups/a2-canvas-rest.png`<br>`docs/04b-ui-mockups/a2-canvas-focus.png` | `docs/04d-physical-view/physical-view-v1.png` |
| 生成元 | `docs/04b-ui-mockups/gen_canvas.py` | `docs/04d-physical-view/gen_physical.py` |
| 選定の経緯 | **A-1/A-2/A-3 の比較の結果 A-2 を採用**（`04b` 8.0節） | 比較・選定を経ていない。1案のみ |
| ノードの見え方 | 平面のガラスタイル | **立体（接地影つきの物理的実体＋半透明の概念モジュール）** |
| 背景 | 点グリッドの観測キャンバス | **同じ点グリッド**（地球は削除済み） |
| 層の示し方 | 縦3帯（ブラウザ／サーバー／データベース） | 空間的な配置＋帯なし |
| ミニマップ | **無い** | ある |
| キャンバス操作（全体表示・拡縮） | **無い** | ある |
| プレビュー／ページ／凡例のフローティング | ある | ある |
| 2状態（初期／フロー集中） | **ある** | 無い（1状態） |

### 判断の材料

- プロンプトの**部品の列挙（ミニマップ・キャンバス操作）は候補B にしか無い**
- プロンプトの「**宇宙空間のような背景**」は**1世代前の記述**である。地球は依頼により削除済みで、現在はどちらも点グリッドの暗いキャンバスである
- 一方、**選定という手続きを踏んだのは候補A** である。候補B は「画面なのか、探索モードの表示方式なのか」も未確定（`04d` 5章）

### 申し送りの推奨

> **候補B（Physical View）を基準画像とし、候補A で確定した「経路の幾何」の規則を持ち込む**のが、プロンプトの記述に最も近い。
> ただしこれは推測である。**実装着手前に依頼者へ確認すること。**
> なお `02c` の画面一覧に Physical View は登録されていない。候補B を採るなら `02b` / `02c` の更新が要る。

## 4. UI部品の分離単位

```
<AppShell>
  <GlobalBar/>                       N0。構成固定
  <Stage>
    <Canvas>                         パン・ズーム・全体表示を持つ
      <FlowScene/>                   ノードとホップ。SVG
    </Canvas>
    <FloatingPanel id="pages"/>      ページ一覧        開閉
    <FloatingPanel id="preview"/>    Webプレビュー      開閉
    <FloatingPanel id="legend"/>     表示設定（凡例）   開閉
    <FloatingPanel id="minimap"/>    ミニマップ         開閉
    <CanvasControls/>                全体表示・拡縮
  </Stage>
  <DetailDock/>                      固定。開閉しない
</AppShell>
```

`<FlowScene>` の内訳：

| 部品 | 役割 |
| --- | --- |
| `<Node>` | 種別アイコン・ステップバッジ・短いラベル・識別子。**属性値は置かない**（UI-15） |
| `<Hop>` | ホップ1本。実測＝連続線／推定＝分節線。**独立した線分として描く**（`03b` 3.3節。隣接ホップを1本に繋がない） |
| `<CutMarker>` | 縦バー＋✕。「追跡しようとしたができなかった」 |
| `<EstimateTag>` | 「推定」チップ。★付きは最弱環 |
| `<DimmedPath>` | 経路外。減光して残す（UI-33。削除しない） |
| `<HoverCard>` | 段階1。1行要約＋観測性の語（`03b` 4.1節） |

> **画像を背景として貼ることは禁止。** 各部品を独立した DOM/SVG 要素として実装すること（プロンプト 4章）。

## 5. 合成データの仕様（架空名に置換済み・これをそのまま使うこと）

### 5.1 置換表

| 設計文書の表記 | 実装で使う名称 |
| --- | --- |
| 物件管理アプリ | **Sample Property App** |
| `/properties` 物件一覧 | **`/listings`** Listings |
| `PropertyCard` | **`ListingCard`** |
| `GET /api/properties` | **`GET /api/listings`** |
| `public.properties` | **`public.listings`** |
| `properties.area` | **`listings.region`** |
| `GET /api/favorites`（経路外） | **`GET /api/saved`** |

IDE 自体の名称（`GRiDDATA`）は仮称のまま使ってよい。実在の顧客名・実DB構造・認証情報は一切使わないこと。

### 5.2 経路（7ノード・7ホップ）

```
① 表示された値「千葉県」
    │ renders   実測
② コンポーネント  ListingCard            src/components/ListingCard.tsx:42
    ╎ derives   推定   「応答のどの項目が、この値になったか」
③ 通信  GET /api/listings — 200 — 124ms
    │ handles   実測
④ サーバー処理  Next.js API Route — 98ms
    │ executes  実測
⑤ 実行SQL  SELECT id, title, region … — 42ms — 12行
    ├ reads    実測  → ⑥ テーブル  public.listings
    └ projects 実測  → ⑦ カラム    region (text)
                              ╎
          maps ★ 推定「カラムと応答項目の対応づけ」→ ③ へ戻る
```

| 項目 | 値 |
| --- | --- |
| 構成要素 | **14 か所**（ノード7 + ホップ7） |
| 実測 | **12** ／ 推定 **2**（`derives` と `maps`） |
| 経路全体の観測性 | **推定**（最弱環に合わせる。OBS-10） |
| 最弱環 | **`maps`（⑦→③）**。同率の `derives` より下流にあるため |

> **⑥→⑦ の線を描いてはならない。** `projects` の始点は `SqlStatement`（⑤）である。
> ⑥→⑦ はオブジェクトモデルに存在しない（`04` 7章 P4-02）。**⑤ から ⑥ と ⑦ へ分岐させること。**

> **件数（14 / 12 / 2）は経路から算出する導出値である。** 定数として埋め込まないこと（`02d` 2.3節）。

### 5.3 異常状態（1件）

| 項目 | 値 |
| --- | --- |
| 事象 | ④ サーバー処理からの外部サービス呼び出しが追跡できない |
| 検出箇所 | `src/lib/notify.ts:18` ／ `sdk.send(...)` |
| 種別 | 未対応の構成（E-07） |
| 表現 | **線を消さず、✕付きの切断マーカーで止める。**「追跡できません／未対応の構成です」 |
| N0 との整合 | 対応範囲インジケータが「部分対応・1件」 |
| 向き | **サーバー帯の外（上方向）へ抜ける。データベース方向へ向けないこと** |

### 5.4 経路外（減光して残す）

`GET /api/saved` と、それが発行した SQL の2ノード。「選択していない経路（このページの他の通信）」と明示する。**削除しないこと**（UI-33）。

## 6. 表示規則（破ると設計の意味が壊れる）

| # | 規則 | 根拠 |
| --- | --- | --- |
| **1** | **一次符号は線の形。色は補助。** 実測＝連続線／推定＝分節線（破線）＋「推定」の語。グレースケールにしても判別できること | NFR-30 |
| **2** | **破線の間隔はスクリーン空間で一定に保つ。** 拡縮しても実測と推定の差が潰れないこと | 同上 |
| **3** | **ノード上に属性値を置かない。** 所要時間・行数・SQL断片・JSON は詳細パネルの担当 | UI-15 / UI-20 / UXR-26 |
| **4** | **経路に対する肯定記号を使わない。** ✓・「検証済み」・確度%・L0〜L3 を出さない | UXR-12 |
| **5** | **正常なノードに状態の記号を付けない。** 記号を出すのは警告・エラー・不明のときだけ | 同上 |
| **6** | **実在が確認できないノードを描かない。** ファイアウォール・CDN・キャッシュ・インターネット・外部APIのアイコンを追加しないこと | OBS-05 |
| **7** | **追跡できない箇所は切断マーカーで止める。** 線を描かないのは「関係が無い」の意味であり、別物 | `03b` 5.2節 |
| **8** | **経路サマリの文言と順序を変えない。** 主張 → 二値の語 → 件数と最弱環 → ★ブロック → 番号付きリスト | `03` 3.5節・10.3節 |
| **9** | **★ブロックは独立した塊にする。** 最弱環が無い経路では丸ごと消せること | `03` 10.4 申し送り1 |
| **10** | **常時表示の文章を増やさない。** キャンバスに語を残すのは「観測できていないこと」＝推定2ホップと切断1件のみ。実測5ホップには語を置かない。外した説明はホバー（段階1）と詳細パネルへ | `04b` 3.1節 |
| **11** | **合成データであることを画面上に常時表示する。** スクリーンショットが単独で出回っても誤解されないため | `04` 1.1節 |
