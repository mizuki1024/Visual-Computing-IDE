## 2. P1-9 — 実プロジェクトを開いている間に合成デモを描かない

### 2.1 方針

* 描くデータセットの選び方に「**プロジェクトの段階**」を足す。段階は開発サーバーの状態と検出結果だけから決める（画面が状態を作らない — 7A の規則のまま）。
  * 検出済み・未起動 → `opened`、検証中・起動中 → `starting`、`running`、`stopping`、`stopped`、`error`。プロジェクト未指定 → `null`
* 段階が `null` でない間は、明示的に選ばない限り、**経路の無いデータセット**（ノード・ホップ・切断・ページが 0。合成のものを1つも持たない）を描き、キャンバスと右ドックに段階ごとの空の状態を出す。
* 実ページの選択・観測（`live`）があれば、従来どおりそれを描く（優先順位は 実ページ ＞ 空の状態 ＞ 合成デモ）。
* 合成デモは「明示的に選んだとき」だけ。［合成デモを見る］・URL の `?data=`。**起動を始めたら選択を解く**（自分のプロジェクトを動かし始めた後に、別のアプリの見本を残さない）。

### 2.2 段階ごとの表示（`src/lib/projectPhase.ts` の `emptyCard`）

右ドックは 03d の4要素（いまの状態・まだ分からないこと・次にすること）、キャンバスは見出しと次の操作だけ。

| 段階 | 見出し | 次にすること |
| --- | --- | --- |
| 起動前（`opened`） | プロジェクトを開きました（まだ起動していません） | 右の「プロジェクトと実行」で［起動］を押してください（起動できない判定のときは「理由を確認してください」） |
| 起動中 | 開発サーバーを起動しています | 起動が終わると、左のプレビューにページが表示されます。そこでページを開いて値を選んでください |

## 3. P1-10 — 描画位置と値の由来を分ける

### 3.1 方針

* **値のノードから DB（テーブル・カラム）へ届いていない経路だけ**、右ドックの経路サマリを分けた形にする。届いている経路（/lin-a の推定・合成・PoC-01・候補が複数の /lin-c）は従来どおり — 「文言と順序を変えない」（03 3.5節）を守る範囲を、届いた経路に限った。
* 分けた形は次の4行。見出しは「選んだ値 — 描画位置と値の由来」で、「この値の出所」とは言わない。

| 行 | 内容 | 例（/lin-g の g-shadow） |
| --- | --- | --- |
| 描画位置 | 特定済み＋観測性の語＋位置＋コンポーネント／特定できません | 特定済み　実測　`src/app/lin-g/page.tsx:28`　LinG |
| 値の由来 | 未確認（DB のどのテーブル・カラムから来たかは、まだ分かっていません） | 未確認 |
| 切れた段階 | 切断の段の語 | 静的解析 |
| 理由 | 切断の理由（段の語を重ねない） | 静的解析で、この値からデータ取得の結果への参照の連鎖を解けません（定数・追えない関数・条件の判定など）（固定値の経路 1 本） |

* その下に「N か所のうち 0 か所が推定です。『実測』は描画位置までの話で、値の出所（DB）が実測で分かったという意味ではありません。」と、語の説明（描画位置・値の由来・未確認）を置く。
* 段は切断（`Cut`）に**表示用の語**として持たせる（`Cut.stage`、省略可）。実ページの由来の評価は `LINEAGE_STAGE_LABEL`（文書の同定・静的解析・実測との照合・実行SQLの SELECT 句）をそのまま使い、ほかに「描画位置の特定」（要素を特定できない）、「値の由来の評価（結果がまだありません）」（評価の前）、「値の由来の評価（この記録では行っていません）」（PoC-02/03/05 の記録データ）、「文書の同定（別の通信）」「経路の描画」を足した。**関係・観測性・切断の位置と本文は変えていない**（`validateDataset()` も同じ結果）。

画面: `docs/07c3-screenshots/1600x1000/05a-lin-g-cut-dock.png`（選択だけ）・`05b-lin-g-cut-with-observation.png`（同じ文書の通信と SQL を並べても「未確認」のまま）・`06-unresolved.png`（描画位置も特定できない）・`04-lin-a-linked.png`（従来どおりの推定経路）。
