## 2. 重なりの根本原因

| # | 原因 | 根拠 |
| --- | --- | --- |
| 1 | **全体表示・寄せの「覆われない領域」が固定値で、プレビューと実行のパネルを知らない** | `freeRegion(vw, vh, leftPanels)` は左の列の有無だけを見る。全体表示は内容をこの領域 x=268..1212 に収めるので、プレビュー（232..624）と実行（894..1224）の下に**わざわざ**並べる。だから全体表示で 5 → 8 個に悪化した |
| 2 | **Phase 5 の後にパネルが大きくなった** | プレビューは 7B-1 で実ページ（iframe 300px）と、7B-2〜7C-1 で選択・由来・観測の行を足して 563px。実行は 7A で所見カードを積み 862px。自動配置の帯（`LANES`）は Phase 5 の小さなパネルを前提に決めたまま |
| 3 | **経路を描いても視点が動かない** | `showLive` は等倍・設計座標のまま。設計座標の 260..1260 × 220..950 に置いたノードが、その位置のパネルの下に入る |
| 4 | **パネルの表示状態が1種類しかない** | 実行中も検出の所見・入力欄・環境変数を全部出す。プレビューも「選ぶ」とき（ページが要る）と「理解する」とき（経路図が要る）で同じ大きさ。閉じると iframe の文書が消える |
| 5 | 最初の視点を決める時点でキャンバスの実寸を測っていない（1440×900 で見つけた） | `viewport` の初期値（設計寸法 1240×952）で「等倍で収まる」と判定し、小さい窓でも全体表示に合わせていなかった |

## 3. 比較したレイアウト方式

数値は実測（1600×1000 / 1440×900 の「DB カラムまで表示」の状態）。k は経路図の倍率、札の文字は 12px × k。

| 方式 | 内容 | 隠れるノード | 倍率 k（札の文字） | 評価 |
| --- | --- | --- | --- | --- |
| 現状 | 固定の `freeRegion`・等倍 | 5 / 7 | 1.0 | 不合格 |
| ズームだけ | 覆われない領域を実寸で求め、パネルはそのまま | 0 / 0 | **0.52 / 0.43**（6.3 / 5.1px） | 指示「ズーム率を下げるだけで解決しない」に反する。読めない |
| **A** 実行パネルを畳む | 実行中は「状態・PID・ポート・停止」と要約の1行（高さ 96px）。［詳細］で全部 | — | 単独ではプレビューが残るので効果が小さい | 採用（B・C と併用） |
| **B** プレビューを畳む | 「理解する」ときはページの表示（iframe）を畳み、アドレス・選択・由来・観測の行だけ残す（高さ 229px）。iframe は DOM に同じ大きさで残す | — | — | 採用（A・C と併用） |
| **C** 実寸の覆われない領域 | 表示中のパネル・操作バー・注記の矩形から、内容を最も大きく収められる矩形を求める | — | — | 採用（A・B と併用） |
| **A+B+C ＋ 経路への自動の収め直し** | 経路を描いた直後に、**経路の範囲**を C の領域へ収める | **0 / 0** | **0.86 / 0.72**（10.3 / 8.6px） | **採用** |
| B' プレビューを左の列へ移す | 畳んだプレビューを幅 236px で左の列（ページと表示設定の間）に置く | 0 / 0 | 同程度（幅で決まるため） | 不採用。横幅は左の列（268px）で決まり、上の帯に置いても倍率は変わらない（下記）。開閉で位置が飛ぶ |
| B'' プレビューを消す | 経路を見るときはパネルを閉じる | 0 / 0 | 0.86 / 0.72 | 不採用。閉じると iframe の文書が破棄され、選んだ要素・ページの文脈が画面から消える |
| G 左の列を自動で閉じる | 狭い画面では「ページ・表示設定・全体」も閉じる | 0 / 0 | 0.94 / 0.79 | 不採用（手動では可能）。凡例（実測と推定の線の区別）が消える。手動で閉じたときの数値は第6.2節・第10節 R-1 |
| H 選んだら選択モードを自動で抜ける | 1回選ぶと選択モードを抜け、すぐ畳む | — | — | 不採用。7B-2 の「選択モードを抜けるまで選び続けられる」動作が変わる |

**横幅が倍率を決める。** 経路図（`/lin-a`、9 ノード）の範囲は設計座標で約 1,090 × 650 の横長で、覆われない領域は「左の列の右（x=268）からキャンバスの右端 − 28」までの幅で決まる（1600×1000 で 944px、1440×900 で 784px）。上の帯（高さ 250px まで）に畳んだプレビュー・実行・操作バーを置いても、高さは足りるので倍率は下がらない。したがって**畳んだパネルを元の位置（左 232・上 16）のまま上の帯に収める**のが、位置を飛ばさずに最大の倍率を得る方法だった。

## 4. 採用した方式と理由

### 4.1 振る舞い

| 場面 | プレビュー | プロジェクトと実行 | キャンバスの視点 |
| --- | --- | --- | --- |
| IDE を開く・検出・起動中・停止中・エラー | 広げる | 全部を出す（入力・所見・理由を読む必要がある） | 従来どおり（等倍、窓が小さければ全体表示） |
| 実行中になった | 広げる（ページを見る） | **畳む**（状態・PID・ポート・［停止する］・「所見 N 件…は［詳細］で」） | 変えない |
| ページを操作する（移動・↻・リンク） | 広げる | — | — |
| ［選択］で選択モードに入る・選んでいる間 | **広げたまま**（選び直せる） | — | 経路を描いたら、残った領域へ経路を収める（この間は小さい: k 0.52 / 0.43） |
| 選択モードを抜ける（選んだ要素が残っている） | **畳む**（ページ表示を隠し、選択・由来・観測の行は残す） | — | 広がった領域へ収め直す（k 0.86 / 0.72） |
| 観測の通信を［表示］ | 畳む | — | 経路を収める |
| ［全体表示］（0 キー） | 畳む（選択モードなら抜ける） | 実行中なら畳む | 経路外も含めて収める |
| ヘッダの［ページを表示 ▾］／［畳む ▴］ | 広げる／畳む（**同じ文書のまま**） | ［詳細 ▾］／［畳む ▴］ | 全体表示のままなら、残った領域へ収め直す |
| 選択の［解除］・停止・再起動 | 広げる | 停止中は全部 | 従来どおり |
| 利用者がパン・拡縮・［ここを見る］をした後 | — | — | 以後、パネルの開閉で勝手に動かさない（03b 8.3節） |

### 4.3 守った UI 方針

* ダーク 2.5D キャンバス・部品・色・線の形（実測は実線、推定は破線）・ノード番号は変えていない。新しいパネルも作っていない
* 右詳細ドック（360px・固定）は変えていない。［ここを見る］・番号キー・Esc の階段もそのまま
* 3ビュー（プレビュー・キャンバス・右ドック）の同期: 畳んでも選択・由来・観測の表示は3か所とも残る
* 観測と推定の表現: 変えていない（推定の語の位置だけ、隠れないように下へ）
* 選択中の要素・表示経路・観測セッション: 畳む・広げる・パネルの開閉で失わない（第7節で計測）

## 6. 実測結果

## 11. 限定試用に進めるかの判断

**題材を固定した、案内つきの限定試用に進めてよい。**

* 7C-0 の判断は「P0 の2件（P0-1 観測の上限・P0-2 パネルと経路図）を直せば、題材を固定した案内つきの限定試用には進めてよい」。P0-1 は 7C-1 で、P0-2 は今回解消した
* 経路は「データとして存在する」だけでなく、**選んだ直後に、隠れずに、読める倍率で**キャンバスに出る（1600×1000 で 86%、1440×900 で 72%）。推定の線（破線）と「推定」の語も見える。右ドックでの確認・プレビューへの戻り・選び直し・停止と再起動も成立した
* 試用の案内に書くこと（7C-0 第10節から更新）
  * 画面は 1600×1000 以上を推奨（1440×900 でも成立するが文字が小さい。左の列を閉じると大きくなる）
  * 「選択」で選び、もう一度「選択」で選択モードを抜けると経路図が広がる。ページに戻るのはヘッダの［ページを表示］
  * パネルは✕で閉じるより［畳む］（ページの文書が残る）
  * 7C-0 の案内のうち「起動後は『プロジェクトと実行』を閉じる」は**不要になった**（実行中は自動で畳む）
  * リンクで移った後は ↻ で読み込み直してから選ぶ（P1-7、未対応のまま）。表示が合成デモに戻っても自分のデータではない（P1-9）
* 利用者自身のプロジェクトでの試用は、引き続き P1-1〜P1-3 を直すまで進めない（7C-0 のまま）
