# Visual Computing IDE（GRiDDATA）

画面に表示されている値が、**どのコードを通り、どのDBカラムから来たのか**を
「証拠のある範囲だけ」で辿るためのローカル開発ツール。

設計の中心にあるのは1つの原則である — **観測できたことと推定したことを混ぜない。**
辿れなかった箇所は、辿れなかったものとして画面に出す（切断マーカー）。

Phase 7A は、実ブラウザで「IDE を開く → プロジェクトを指定する → 起動する →
起動状態を確認する → 停止する」を端から端まで通した（`tests/runtime-e2e.spec.mjs`）。
**実測で起動まで確認した Next.js は 16.4.3（`poc/fixture-app`）と 15.5.5**
（15.5.5 は同じ構成で新しく組んだ最小の題材。利用者の実在プロジェクトではない）。
起動できない構成（上の階層の lockfile など）は理由を起動前に出し、`next dev` 自身が
対象の `tsconfig.json` / `next-env.d.ts` を書き換えることは主体を明示して伝える。
詳細と未対応事項は `docs/07a-implementation-report.md`。

Phase 7B-1 は、IDE が起動した開発サーバーのページを**既存のプレビューパネル**に表示する。
ブラウザとサーバーの localhost が違うクラウドの環境でも届くよう、IDE 側に**宛先を1つに固定した中継**
（別ポート・別 origin、既定 3150）を置き、iframe はその中継の URL を開く。起動先の `next dev` には
**許可リストの環境変数だけ**を渡す（IDE の秘密情報を渡さない）。詳細は `docs/07b1-implementation-report.md`。

Phase 7B-2 は、プレビューのバーの［選択］を押して実ページの要素をクリックすると、その要素を描いた
React コンポーネントとソース位置（ファイル・行・列）を、既存のキャンバスと右ドックに根拠つきで出す。
方式は PoC-03 のビルド時の要素識別子注入で、iframe からは識別子だけを受け取り、位置は IDE が対応表と
ソースの読み直しで決める（6段の照合。1つでも欠ければ理由つきで「特定できません」）。
注入は対象の `next.config` が `POC03_ANCHOR` でローダを読む設定のプロジェクトに限る（IDE は設定を書き換えない）。
詳細は `docs/07b2-implementation-report.md`。

Phase 7B-3A は、IDE が起動した開発サーバーで**いま起きた**通信・サーバー処理・SQL を、既存のキャンバスと右ドックに出す。
通信はプレビューの中継が転送したその場で記録し（取得手段 `preview-relay`。`02d` 1.3.3）、計装が応答の専用ヘッダに載せた
トレース識別子でサーバー側のスパンへ、その子孫の SQL へ結ぶ。テーブル・結果列は Phase 6F の SQL 解析器で決める。
トレース識別子が無ければ結ばない（時間の重なりで推定しない）。表示された値・コンポーネントとはまだ結ばない（7B-3B）。
観測は起動ごとのセッションで、停止・再起動で消える。詳細は `docs/07b3a-implementation-report.md`。

Phase 7B-3B-1 は、Server Component の実行中に起きた SQL について、**それを実行したデータ取得の呼び出し位置**
（`DataAccessSite`。ファイル・行・列と囲むコンポーネント）を特定し、`queries` で SQL に結ぶ。方式は PoC-02 の
呼び出しの入口のスタック（`POC02_CALLSITE`）・ソースマップの戻し・ソースの読み直しをそのまま使い、同じ起動・同じスパン・
実行の後に書き換わっていないことを足して確かめる。通信と受付スパンは、中継が要求ごとに作る識別子で結ぶ
（同じパスの別の要求への付け替えを検出する）。**選択した値と SQL は結ばない**（値の由来は未確認と書く）。
詳細は `docs/07b3b1-implementation-report.md`。

Phase 7B-3B-2 は、プレビューで選んだ要素の値について、**その要素を描いた文書の通信**を中継が応答ごとに付ける識別子で同定し、
PoC-04 の静的解析（`lineage.mjs`）が見た「値 → データ取得の呼び出し」を、**その文書の通信で実測した呼び出し位置**（列まで）と
**実行された SQL の SELECT 句**に照合してから `supplies`（`DataAccessSite → PropBindingSite`・L2）を作る。
どれか1つでも欠ければ線を作らず、欠けた段（文書の同定／静的解析／実測との照合／SELECT 句）と理由を出す。
候補が複数なら候補のまま出す。あわせて preview-e2e の環境変数の検査を「名前」から「値と出所」に直し、
呼び出し位置の照合で PID が片方でも欠ければ `queries` を作らないようにした。詳細は `docs/07b3b2-implementation-report.md`。

## 動かす

```bash
npm install
npm run dev          # http://127.0.0.1:3100
```

探索画面は、記録済みの観測データを9通り切り替えて描ける（同じ描画部品を通る）。

```
/              合成シナリオ（UI の基準）
/?data=measured  PoC-01 の実測
/?data=elements  PoC-03（表示された値・コンポーネント）
/?data=flows     PoC-05（通信を開始したコンポーネント）
/?data=rsc       PoC-02（Server Component の直読み）
/?data=rsc-svc   PoC-02（サーバー内部の通信が1段入る）
/?data=lin-a     PoC-04 由来を1列に絞れた場合（推定の関係が1本入る）
/?data=lin-c     PoC-04 候補が複数のまま（1つに断定しない）
/?data=lin-g     PoC-04 由来を作らない（切断のまま）
```

画面右上の「プロジェクトと実行」パネルから、**実在するローカルの Next.js
プロジェクト**を指定して開発サーバーを起動・停止できる（Phase 7A）。
起動すると、プレビューパネルにそのページが出る（Phase 7B-1）。
プレビューのバーの［選択］を押してページの要素をクリックすると、React のソース位置が右の詳細に出る（Phase 7B-2）。
プレビューのバーの下の「観測（いまの起動）」の一覧から通信を選んで［表示］を押すと、その通信のサーバー処理・SQL・テーブル・カラムが出る（Phase 7B-3A）。
SQL を実行した呼び出し位置を特定できたものは「コンポーネント」のノードとして並ぶ。要素を選んでから同じパスの通信を［表示］すると、
選んだ要素の React のソースと SQL の呼び出し位置を同じキャンバスに並べる（両者の間に線は引かない — Phase 7B-3B-1）。

**クラウドの開発環境（Codespaces など）で使うとき。** ブラウザは転送 URL で来るため、IDE は既定では
API を拒否する（ループバックだけを受け付ける）。IDE を起動するときに、許可するホスト名を明示する。
ワイルドカードは受け付けない。ポートの公開範囲は Private のままにすること。

```bash
# Codespaces（IDE のポート 3100 と、中継のポート 3150 の転送ホストを組み立てる）
VCIDE_ALLOWED_HOSTS=codespaces npm run dev
# それ以外の転送
VCIDE_ALLOWED_HOSTS=ide.example.test VCIDE_PREVIEW_ORIGIN=https://preview.example.test npm run dev
# シェルの環境変数に頼るプロジェクトは、渡す名前を明示する（既定では渡さない）
VCIDE_CHILD_ENV_PASS=DATABASE_URL npm run dev
```

### 検証

```bash
npm run typecheck
npm run build
npm test             # ブラウザを使う節は dev サーバーが :3100 に必要（新しく起動した IDE に対して回す）
npm run runtime:reap # 孤立した開発サーバーの掃除
```

`npm test` のうちブラウザを使う節は `BASE`（既定 `http://localhost:3100`）に
対して実行する。最後の `tests/runtime-e2e.spec.mjs` は実際に開発サーバーを起動・停止する
（題材は既定で `poc/fixture-app`、`VCIDE_E2E_PROJECT` で変えられる）。「開いた直後」の
3項目は**新しく起動した IDE でしか確かめられない**ため、同じ IDE で続けて回すと skip になる。
`tests/preview-e2e.spec.mjs` は **IDE を自分で起動し**（`.next` のビルドが要る）、クラウドの転送を模した
ブラウザ（ブラウザの 127.0.0.1 がサーバーに届かない構成）で実プレビューを確かめる。
`tests/select-e2e.spec.mjs` も同じく IDE を自分で起動し、実ページの要素の選択とソースの特定を確かめる。
`tests/observe-e2e.spec.mjs`（7B-3A）も IDE を自分で起動し、いまの起動の HTTP・SQL の観測を確かめる。
`tests/queries-e2e.spec.mjs`（7B-3B-1）も同じく、SQL の呼び出し位置・同じパスへの並行要求・選択した要素との並べ方を確かめる
（DB 必須。`VCIDE_E2E_NO_DB=1` でも skip にせず失敗にする）。
**題材の DB（`poc/README.md` の使い捨て PostgreSQL と、`poc/fixture-app/.env`）が要る。** 届かなければ失敗にする
（SQL の観測を確かめずに通過させないため）。DB 無しで回すと明示する場合だけ `VCIDE_E2E_NO_DB=1`（SQL の節を skip と数える）。
探索の試験（`explore` / `measured` / `flows` / `rsc`）は、ページを開くたびに右上のパネルを閉じて前提をそろえる
（`tests/lib/canvas-precondition.mjs`）。一度起動・停止した IDE でも、同じ IDE で `npm test` を続けて回しても通る（`docs/07b2` 7.3節）。
ブラウザは既定で Chrome（`PW_CHANNEL=none` で同梱の chromium）。`poc/` の PoC ランナーは Docker の Postgres を使うため、
既定のテストには含まれない（記録済みの観測結果を読む）。

## 構成

```
src/app/          画面（App Router）と プロセス管理 API（/api/runtime/*）
src/components/   描画部品。合成でも実測でも同じ型を受け取る
src/lib/          model（関係モデルの契約）/ adapter / layout / derive
src/data/         記録済みの観測結果（PoC-01〜05 の実測。書き換えない）
src/server/       Node 側。プロジェクト検出・開発サーバーの起動停止・入口の防御
src/state/        画面の状態（探索 / 実行）
tests/            1,464 件。純粋な層は素の Node、画面は実ブラウザで見る
poc/              PoC-01〜05 の検証用アプリとランナー（IDE 本体には含めない）
docs/             要件から実施報告まで。**実装の根拠はすべてここにある**
```

## 守っている約束

| | |
| --- | --- |
| 観測性は1か所で決まる | `observabilityOf(source)` だけ。ホップやノードが自分で決めない |

| 対象プロジェクトを書き換えない | 計装は `NODE_OPTIONS` の前置だけ。ファイルを置かない |
| 任意のコマンドを実行しない | 起動するのは対象の `node_modules` の next だけ |
